# 사례 지식 — 가장 가까운 화장실

> 공공데이터 공중·개방화장실로 **모바일에서 현재 위치 기준 가장 가까운 화장실**을 보여 주는 개인 개발 사례(비영리).
> 착한가격 지도(`../착한식당`)의 모듈 문서를 재사용한다: 공공데이터-파이프라인 · 외부플랫폼-레퍼런스 · 분류-검색매핑 · 지식화-프로세스.
> 각 항목은 **원칙 → 이번 근거(수치)** 순서. 진행 방식: 의견 → 목업 → 결정 → 적용.
>
> **문서 지도** — 사건과 재발 방지는 [버그이력](버그이력.md), 다음 작업 시작점은 [앱구현-시작점](앱구현-시작점.md),
> 배포·운영 설정과 함정은 [배포설정기록](배포설정기록.md).
> 다른 프로젝트에도 쓰는 원칙은 착한가격 저장소의 모듈 문서로 올린다: [위치 매칭·정확도 등급](../../착한식당/docs/위치매칭-정확도등급.md) · 공공데이터-파이프라인 · 분류-검색매핑 · 외부플랫폼-레퍼런스 · 지식화-프로세스.
> 문서끼리 어긋나지 않았는지는 `python check_docs.py`로 확인한다.

### 1-5. 서비스 원칙 (2026-09-22, 사용자 의견 → 결정)
- **정확한 위치만 보여 준다.** 급한 사람이 믿고 갔는데 못 찾거나 사실과 다르면 안 보여 준 것보다 나쁘다. 하부 주소(번지·건물번호)가 없거나, 범위가 넓거나, 좌표를 정확히 못 구한 곳은 **표시하지 않는다**(데이터에는 남기고 숨김).
- **도시 지역이 핵심.** 농어촌·산간을 일부러 빼는 게 아니라, 정확도 기준을 엄격히 하면 자연히 도시 중심이 된다 → 전체 변환 후 시·구/군 지역별 표시율로 확인.
- **내 위치가 먼저:** 모바일에서 위치 권한을 먼저 요청. 거부하면 **도로명주소 또는 번지까지** 입력받아 기준점으로 쓴다(동·도로명만 입력은 받지 않음 — 같은 정확도 기준).
- **좌표 등급별 표시(결정):** A 건물·B 필지 표시 / **B산 표시 + "산지에 있음"**(공원·등산로 입구처럼 지목이 임야인 곳) / C 대략 숨김(동·리·도로명까지만) / X 숨김. P 장소는 전체 결과 후 결정.
- **도보 길찾기로 연결:** 가까운·지금 이용 가능한 곳을 고르면 외부 지도 도보 길찾기로 넘긴다(네이버·카카오·구글 링크, 크롤링 없이 링크 연계).

## 2. 주소 정제·좌표

### 2-1. 도로명주소 API (`addr_util.py`, `refine_address.py`)
착한가격 모듈을 가져오면서 **이 데이터에 맞지 않는 가정 두 가지**를 고쳤다.
- **결과가 여러 건이면 첫 번째 채택 → 틀린 건물.** 착한가격은 번지까지 있는 가게 주소라 문제없었지만, 여기는 번지 없는 주소가 있다(`금산군 복수면 곡남리` 264건, `대전광역시 서구` 24,966건). → 여러 건이면 **주소 끝(도로명+건물번호, 동·리+번지)이 정확히 같은 후보**만 채택(`봉양로408` ≠ `봉양로408번길 5`), 없으면 '모호'. 400곳 시험에서 모호 16 → 4, 남은 4곳은 번호 없는 도로명(`관음로`, `경부고속도로`).
- **결과 지역 검증:** 자치단체코드(228개)마다 주소가 온전한 행에서 가장 많은 시도·시군구를 뽑아, 결과가 그 밖이면 '지역불일치'로 버린다(`서구`·`동구`처럼 여러 시에 있는 이름 대비).
- 도로명주소 API는 줄임말(`울산`), 띄어쓰기 없음(`경상남도창원시성산구…`), 옛 이름(`광주광역시` → 전남광주통합특별시)을 알아서 처리한다.
- **'주소없음' ≠ 틀린 주소:** 도로명주소 DB는 건물이 있는 곳만 있어, 공원·산책로·계곡 같은 **건물 없는 필지는 주소없음**이 된다(시험 400곳 중 지번만 66곳 → 57곳 주소없음). 이런 곳은 카카오가 필지 좌표를 준다.
- 함정: Windows의 curl로 한글 검색어를 보내면 글자가 깨져 숫자만 검색된다(`울산 남구 삼산로 100` → 제주 주소). 시험도 실제 스크립트와 같은 Python 요청으로 한다.

### 2-2. 좌표 정확도 등급 (`geocode_toilets.py`)
카카오 주소검색의 `address_type`으로 정확도를 나눈다 — 좌표 하나가 아니라 **"얼마나 믿을 수 있는 좌표인가"를 같이 저장**(파이프라인 6장 '출처·신뢰도').

| 등급 | 카카오 종류 | 뜻 |
|---|---|---|
| A 건물 | ROAD_ADDR | 건물 위치 |
| B 필지 | REGION_ADDR | 번지 위치(건물 없는 야외) |
| B산 | REGION_ADDR + 산 | 임야 번지 — 넓어서 오차 큼 |
| P 장소 | 장소검색 | 주소가 대략일 때 시군구+화장실명으로 찾음(이름 유사·3km 안) |
| C 대략 | ROAD·REGION, 본번·동리 대체 | 도로 가운데·동리 중심 — 수백 m~수 km |
| X 실패 | — | |

- **문제:** 이 데이터에는 건물관리번호로 맞출 수 없는 곳이 많고(공원·하천·체육시설), 도로명과 지번 중 어느 쪽이 맞는지 알 수 없는 경우가 있다.
- **결정:** 주소로 판단하지 못하거나 좌표를 못 구한 곳은 **화장실명·주소에서 읽히는 시설명**으로 카카오·네이버에서 찾아 **시설 위치**를 쓴다. 포털 장소로 연결해 사용자가 직접 확인할 수 있게 하고, **넓게 잡힌 위치라는 것과 우리가 매핑했다는 것을 고지**한다.
- 등급: **확인**(카카오·네이버가 150m 안에서 일치) 567곳 / **추정**(한 곳에서만 — 네이버가 더 방대) 372곳. 조건: 이름 3글자 이상, 시군구 안, 원본 주소에서 5km 안(동명이소 방지), 이름 유사 0.7 이상 **또는 이름이 통째로 들어 있고 덧붙은 말이 다른 종류가 아닐 것**.
- **이름 포함 규칙(2026-09-23 보강):** 유사도만으로는 `대흥주유소`↔`S-OIL 대흥주유소`(맞음)와 `계산역`↔`계산역아파트`(틀림)가 둘 다 0.67로 같다 → 우리 이름이 상대 이름에 통째로 들어 있고, 덧붙은 말이 **다른 종류**(아파트·노인정·학원·역·호선·터미널 등)가 아닐 때만 채택. 단 우리 이름이 이미 같은 종류면 허용(`부천역` → `부천역 1호선`). 영문 줄임말도 맞춘다(`오성아이씨주유소` → `오성IC주유소`). 46곳 추가로 살아남.
- **좌표 실패(X)도 시설 이름으로**(사용자 결정): 좌표가 아예 없어 숨기던 곳도 이름으로 찾으면 "추정"으로 표시. **대략 좌표(C)는 쓰지 않는다** — 동·면 중심점이라 특정할 수 없음(사용자 결정).
- 앱 표시: `w='F'` + `pc=1/0` → "**시설 위치 기준** · 입구·안내판 확인" / "**이름으로 찾은 위치** · 정확하지 않을 수 있어요" + 포털 장소 링크. 정확한 주소로 얻은 건물 좌표(A)는 안내 없이 그대로.
- 효과: 표시 50,746 → **51,548곳(96.2%)**, 카드 50,323장. 시설로 살린 곳의 원래 등급: X 319 · C 290 · P 183 · A 146. 남은 숨김 X 248 · C 440, 확인 목록 409 → **262**. 좌표의 실제 시군구 확인 표본 400곳 **전부 일치**.
- 원칙: 주소가 아니라 **장소(시설)로 맞추는 길**을 하나 더 둔다 — 단, 출처와 확신 정도를 화면에 밝힌다(착한가격 "출처·신뢰도·확인일" 원칙의 확장).

### 6-2. 쉬는 날의 "열림" — 원문이 말한 요일이 먼저, 아니면 종류로 낮춘다 (2026-09-24 결정·적용)
문제: 공휴일(추석)에도, 일요일에도 평일 시각 그대로 **"열림"** 이 떴다. 원본은 요일·공휴일을 거의 말하지 않는다 — **공휴일 표기 81곳**, 요일을 말한 카드 **2,290곳**(시각형 21,228곳 중 10.8%). 요일 말이 없으면 해석기가 **매일**로 두기 때문이다.

결정한 순서(사용자 결정)
1. **원문이 그 날을 직접 말했으면 그 말을 따른다.** 토·일 카드에 `(주말)09:00~18:00`, `(토)…`처럼 적혀 있으면 주말에도 **열림 그대로**. 공휴일은 `(공휴일)…` 표기가 있는 카드만 그대로.
2. 말한 적이 없으면 **시설 종류**로 낮춘다 — 관공서·공공시설·문화·관광·대학·민간시설은 쉬는 날에 **"공휴일 확인" / "주말 확인"**(회색) + "닫혀 있을 수 있어요".
3. 24시간·상시(26,298곳)와 역·터미널·주유소·공원·시장·상가·병원·체육·종교 등은 **손대지 않는다**.
4. 공휴일은 **법정공휴일(한국천문연구원 특일 정보)** 기준 — `app/data/holidays.json`(2026·2027).

이를 위해 원문이 말한 요일을 데이터에 남겼다: `hours.py`가 `said`(직접 말한 요일)를 돌려주고, 앱 데이터의 개방시간에 **`dw`(요일 비트)** 로 실린다. 앱은 `cardState()` 한 곳에서 이 판단을 하고 목록·필터·묶음 카드가 모두 같은 답을 쓴다.

| 날 | 그대로 열림 | 낮춤 |
|---|---|---|
| 공휴일 | 공휴일 시간이 적힌 81곳 | 13,117 |
| 토요일 | 토요일을 말한 452곳 | 11,654 |
| 일요일 | 일요일을 말한 453곳 | 11,650 |

확인(서울시청 500m 26곳): 평일 **26곳 열림** / 토·일 **12곳 열림 + 14곳 "주말 확인"** / 추석·개천절 **12곳 + 14곳 "공휴일 확인"**. `(평일)09:00~20:00+(주말)09:00~18:00`인 한림청소년문화의집은 토·일 열림(19시엔 닫힘), 개천절엔 "공휴일 확인".

남은 한계: `(평일)+(주말)`을 모두 적은 329곳도 **공휴일에는 낮춘다**(공휴일을 말한 적은 없으므로). 명절 당일 휴관이 흔한 박물관·문예회관을 생각하면 보수적인 쪽이 맞다고 봤다.

데이터로 확인한 것
- **더현대 대구는 원본에 없다.** 대구 백화점은 `롯데백화점 대구점`(북구) 한 곳뿐. 백화점·대형 상가는 민간이라 **지자체에 개방화장실로 신고되지 않으면 데이터에 없다** — 우리가 숨긴 것이 아니다. 앱의 "알아보기"에 이 한계를 적는다(3단계).
- **대구 도심 목록이 비어 보이는 진짜 이유**: 대구 중구 116곳 중 **91곳(78%)이 개방시간 코드 `불규칙`**. 상세에는 `08:00~24:00`처럼 시각이 또렷한데도 코드를 우선해 "시간 확인"으로 내린다. 전국 518곳(강원 330 · 대구 98 · 인천 30) — 배포 전 결정 항목이었던 것이 실제 피해로 확인됨(5-4).

### 6-4. 코드 '불규칙' + 시각 → 시각을 따른다 (2026-09-24 사용자 결정·적용)
원본에는 개방시간이 **코드(상시·정시·불규칙·미개방)** 와 **자유 입력 상세** 두 칸으로 들어온다. 코드가 `불규칙`이면 상세에 `08:00~24:00`처럼 시각이 또렷해도 "시간 확인"으로 내렸었다. 실제 피해: **대구 중구 116곳 중 91곳(78%)이 이 경우** — 도심 목록이 비어 보였다(6-3).

결정: **코드보다 상세를 따른다.** 코드가 `불규칙`이라도 상세에서 시각을 읽어낼 수 있으면 그 시각으로 계산하고, 카드에 **"적힌 시각 기준(원본 표기 '불규칙') · 시간이 바뀔 수 있어요"** 를 붙여 **어디서 온 판단인지 밝힌다**. 시각을 못 읽으면(말로만 적힌 경우) 예전대로 "시간 확인".

- 근거: 행안부 점검표상 시각을 적으면 코드는 `정시`여야 한다 → 코드를 잘못 고른 입력 실수로 보는 편이 맞다. 두 칸이 어긋나면 **정보가 더 많은 쪽**이 사실에 가깝다.
- 규모: 전국 518곳(강원 330 · 대구 98 · 인천 30) → 카드 기준 **확인 필요 3,786 → 3,412(−374)**, 시각 21,709 → 22,042.
- 대구 중구 기준점 500m(24곳): 평일 낮 **열림 5 → 24곳**(19곳이 이 규칙 덕분), 평일 밤 10시 5 → 8곳.
- 회귀: `test_hours.py` 61항목(불규칙+시각 → 열림, 불규칙+말 → 확인 필요 포함), `test_hours_js.py` 710구조 × 8시각 일치, `golden.py` 변화 없음.

### 6-5. 첫 화면 심미성 — 유리 아이콘 박스 (2026-09-24 사용자 결정, B안)
문제: 첫 화면 아래를 **흰 카드 블록**이 차지해, 이 앱의 첫인상인 배경 그림(시간대별 하늘)을 가렸다.

**B 채택.** 반투명 유리(배경 blur 10px, 흰 테두리 55%)로 그림이 비치고, 주 버튼(`내 위치로`)만 인디고→바이올렛으로 채워 어디를 누를지 분명하다. 박스마다 **아이콘 + 이름 + 한 줄 설명**(`가장 빠른 길` / `주소·건물 이름`).
- `지금 어디세요?`는 카드 밖 흰 글씨(그림자)로 올려 블록을 없앴다.
- C(3칸)는 하나하나가 작아지고, D는 앱 하단 탭처럼 보여 "첫 화면"의 느낌이 준다 — 둘 다 제외.
- 교훈: **배경이 서비스의 첫인상이면, UI는 그 위에 얹되 가리지 않는다.**

### 6-6. 이름으로 찾아왔으면 그 장소를 맨 위에 (2026-09-24 사용자 제안·적용)

### 6-7. 위치 정하는 화면을 하나로 (2026-09-24 사용자 지적 → B안)

검토한 안: A 선택 시트(한 번 더 누름) · **B 핀 화면에 검색창 상시 + 내 위치 단추** · C 기준 바에 아이콘 두 개(작아서 누르기 어려움) · D 작은 링크만(눈에 안 띔).

**B 채택 — 핀 화면 하나로 세 갈래를 다 받는다.**
- 위: **검색창**(지금 기준 주소가 들어 있고, 누르면 검색 화면) + `🏠 처음`
- 가운데: 고정 핀(그대로), 오른쪽 아래: **`◎` 내 위치** 단추 — 지도를 끌다가 되돌아오는 길
- 아래: 주소 + `여기 맞아요`(그대로). 위치를 못 받으면 화면을 막는 알림 대신 **지도 위에 안내**를 띄운다.

함께 고친 것 — **화면 이동을 브라우저 이력에 넣었다**(`history.pushState`).
- 앱 안의 `<`도, **휴대폰의 뒤로 가기**도 한 단계씩 돌아간다(전에는 뒤로 가기가 앱을 닫았다).
- 확인: 목록 → 위치 바꾸기 → 검색 → 뒤로 = 핀 → 목록 → 핀 → 첫 화면.

### 6-8. 보기 설정 — 어두운 모드·큰 글씨 (2026-09-24 사용자 요청·적용)
급할 때 쓰는 앱이고 어르신도 쓴다. 첫 화면 오른쪽 위 **`⚙`** 하나에 두 가지를 담았다(설정만 저장, 위치는 저장하지 않는다).

| 설정 | 값 | 방법 |
|---|---|---|
| 화면 | 밝게 · 어둡게 · **기기 설정(기본)** | 색을 `:root` 토큰 23개로 모아 두고 `[data-theme="dark"]`에서 값만 다시 정의 |
| 글씨 크기 | 보통 · 크게(+12%) · 아주 크게(+25%) | 화면의 모든 크기를 **rem**으로 바꾸고 루트 글자 크기만 16 → 18 → 20px |

- **rem 전환이 핵심**이었다(글자 39곳·아이콘 크기). 글자만 키우면 아이콘이 따로 놀아 더 읽기 어려워진다 — 함께 커져야 한다.
- 큰 글씨에서는 **이름 두 줄 허용**, **픽토그램 줄바꿈 허용**(안 그러면 잘린다).
- 어두운 모드의 함정 둘: ① `background:#fff`처럼 **박아 둔 흰색**이 남아 있으면 흰 판에 흰 글씨가 된다 → 모두 `var(--paper)`로. ② **`input`은 글자색을 물려받지 않아** 검게 나온다(T18) → 폼 요소는 색을 따로 준다. 카카오 지도는 어두운 타일이 없어 밝게 남으므로 `filter: brightness(.88)`로 눈부심만 낮췄다.
- 어두운 모드에서는 첫 화면 배경을 **밤 그림**으로 고정(시간대 자동 선택보다 우선).
- 깜빡임 방지: 저장된 설정을 `<head>`의 짧은 스크립트가 **그리기 전에** 입힌다.

함께 고친 것
- **누르는 자리 44px 이상**(전에는 `처음` 31 · `지금 열림` 32 · `위치 바꾸기` 35px) — 어르신·흔들리는 차 안.
- **목록에서 반경 바꾸기**: `300m · 500m · 1km` 칩을 `지금 열림` 옆에(전에는 결과가 없을 때만 넓힐 수 있었다).
- 첫 화면 주 버튼(`내 위치로`)의 투명도를 높여(0.85 → 0.6) 배경 그림이 비치게 — 유리 박스의 뜻을 살렸다(사용자 의견).
- 첫 화면 제목 **125%**(36 → 45px, 작은 화면은 `12.5vw`로 자동 축소), 부제 13 → 16px — 영화 포스터 느낌.

**2·3단계에서도 지킬 규약**(새 화면을 만들 때)
1. 색은 **토큰만** 쓴다(`var(--ink)`·`var(--paper)`…). `#fff`·`#000`을 직접 쓰지 않는다.
2. 글자·아이콘 크기는 **rem**으로 쓴다(px 금지). 1rem = 16px 기준.
3. 누르는 것은 **최소 44px**.
4. 새 화면을 만들면 **어둡게 + 아주 크게**로 한 번씩 보고 넘어간다.

### 6-9. 구글 도보 길찾기는 국내에서 안 된다 (2026-09-24 확인)

| 부르는 방식 | 결과 |
|---|---|
| `google.com/maps/dir/?api=1&origin=…&destination=…&travelmode=walking` | **"경로를 찾지 못했습니다."** |

- **버튼이 있다고 되는 것이 아니다**: 구글 지도 화면에는 도보(사람 아이콘) 선택지가 늘 보인다 — 전 세계 공통 UI다. 목적지를 넣고 눌러야 "서비스 범위를 벗어났다"는 답이 온다(사용자 확인 → 재검증).
- 교훈: 해외 서비스의 기능은 **국내에서 끝까지 눌러 보고** 넣는다 — 화면에 선택지가 있는 것, 문서에 "지원"이라 적힌 것, 실제로 결과가 나오는 것은 모두 다르다.

- **네이버 거리뷰를 못 넣는 이유(사용자가 보내 준 실제 URL로 확인)**: `…/place/12247764?…&p=oq39GNGb0Z8nn5RZuhujYA,153.1,10,80,Float` — `p=` 뒤가 좌표가 아니라 **파노라마 고유 ID**다. 앞의 `place/…`도 네이버 플레이스 ID로, 공식 API로는 받을 수 없다. → 위경도·이름·주소로는 만들 수 없다.
- **카카오가 좌표로 보이는 이유**: PC 웹은 이름이 들어간다(확인: `link/to/서울시청,37.5665,126.978` → 목적지 칸 "서울시청"). **휴대폰에서 앱으로 열리면 좌표**로 보인다 — 카카오 앱 스킴에 목적지 이름 인자가 없다. 장소 ID가 있는 곳은 "카카오 장소"로 열면 이름 그대로다.
- 오류 신고 문구를 사용자 의견대로 바꿨다: "원본은 지자체가 고칩니다…"(방어적) → **"이 정보는 각 지자체가 관리합니다. 틀린 내용이 있으면 관리기관에 알려 주세요."**

### 6-13. 찾은 곳에 없을 때 — 말을 두 가지로 나눴다 (2026-09-24 사용자 동의)
"없다"는 한 마디로 끝내면 막다른 길이고, 설명이 틀리면 더 나쁘다. 그래서 **검색한 이름의 종류로 갈라** 말한다.

| 검색한 곳 | 화면 |
|---|---|
| **대형 민간시설**(백화점·마트·아울렛·타워·호텔·시네마…) | **○○에는 등록된 화장실이 없어요** — 민간 건물은 지자체에 신고된 곳만 공공데이터에 들어옵니다. 실제로는 있을 수 있으니 **안내 데스크에 물어보세요.** |
| 그 밖(공원·역·관공서 등) | **'○○' 이름으로 등록된 곳은 없어요** — 그 안의 화장실이 **다른 이름으로** 등록돼 있을 수 있습니다. 아래 목록을 봐 주세요. |

- 둘 다 **가장 가까운 곳까지의 거리**를 함께 적는다(롯데백화점 상인점 92m · 두류공원 298m).
- 두 번째 문구가 중요하다: 두류공원을 검색하면 공원 안 화장실이 `두류수영장`·`2.28화장실`·`시계탑삼거리화장실`처럼 **다른 이름으로** 들어 있다. "없다"고 단정하면 거짓말이 된다.
- 원칙: **우리가 아는 것("이 이름으로 등록된 것이 없다")과 사실("화장실이 없다")을 구분해서 말한다.**

### 6-14. 첫 화면 글꼴 — 송명 → Noto Serif KR 300 (2026-09-24 사용자 결정, 3안)
"제목 굵기를 85%로" 요청에서 시작했는데, **송명(Song Myung)은 굵기가 400 하나뿐**이라 굵기를 낮출 수 없었다(가변 폰트 아님). 네 안을 목업(`design/title_weight.html`)으로 비교했다.

| 안 | 방법 | 결과 |
|---|---|---|
| 1 | 지금(송명 400) | 기준 |
| 2 | 송명 + 불투명도 72%·그림자 축소 | 획은 그대로, 인상만 가벼움 |
| **3 채택** | **Noto Serif KR 300(Light)** | 진짜로 가는 획 — 요청에 가장 가까움 |
| 4 | Noto Serif KR 200 | 너무 가늘어 낮 배경에서 묻힘 |

적용 범위(사용자 결정): **제목·부제·"지금 어디세요?"는 명조**, **버튼 글씨는 고딕 유지**. 첫 화면은 *보는 곳*과 *누르는 곳*이 섞여 있어, 보는 곳은 분위기·누르는 곳은 또렷함으로 나눴다.
- 명조가 송명보다 **넓어서** 제목이 화면에 닿을 뻔했다 → `min(45px,12.5vw)` → `min(44px,11.8vw)`(글자 폭 344px/375px).
- "지금 어디세요?"는 사진 위라 300은 약해 **400**으로, 밝은 낮 배경을 위해 그림자를 `.5 → .75`로.
- 교훈: **글꼴을 바꾸면 폭·굵기·배경 대비를 다시 잰다.** 굵기가 하나뿐인 폰트는 나중에 조절할 여지가 없다.

### 6-17. 구글 링크의 한계 두 가지 (2026-09-24 확인)
- **구글 지도는 좌표로만 열린다.** 이름을 붙이는 옛 문법(`?q=위도,경도(이름)`)은 지금 웹에서 **무시**되고(좌표만 표시), 이름+주소로 텍스트 검색하면 **엉뚱한 가게**가 잡힌다(`대구역 …태평로 161` → 닥터하스킨 대구점). 국내 장소 이름을 구글이 갖고 있지 않기 때문 → **좌표로 두고 "좌표로 표시됩니다"를 적었다.**
- **구글 스트리트뷰는 뺐다.** 국내에 없는 곳이 많아 **검은 화면**이 뜬다(사용자 확인). 로드뷰는 카카오만 남겼다.
- 정리하면 구글은 국내에서 **도보 길찾기 ×(6-9) · 장소 이름 × · 거리뷰 대부분 ×** — 위치 보기 용도로만 쓴다.

### 6-18. 카카오가 검색에서 무엇을 주는가 (2026-09-24 확인)
"주소를 치면 시설 이름도 오는가"를 실제로 찍어 확인했다.

| 검색 | 돌려주는 칸 | 시설 이름 |
|---|---|---|
| **장소 검색**(`places.keywordSearch`) | `place_name` · `category_name`(`가정,생활 > 백화점 > 롯데백화점`) · `category_group_name` · `phone` · `id`(장소 ID) · `place_url` · `road_address_name` · `address_name` · `x,y` · `distance` | **있음** |
| **주소 검색**(`geocoder.addressSearch`) | `address_name` · `address_type` · `address`(지번) · `road_address` · `x,y` | 없음 — 그러나 **`road_address.building_name`에 건물명**이 온다(`태평로 161` → **롯데백화점 대구역**) |

- 그래서 **주소를 쳐도 시설 이름을 보여 줄 수 있다.** ① 장소 검색이 주소 문자열에도 결과를 주고(`대구 북구 태평로 161` → 롯데백화점 대구점·유니클로·대구역), ② 그래도 없으면 주소 검색의 **건물명**을 이름으로 쓴다.
- **업종은 끝이 아니라 한 칸 앞을 쓴다**: `가정,생활 > 백화점 > 롯데백화점`의 끝은 **브랜드**다 → `백화점`(종류)을 보여 준다.
- 핀 화면도 같은 원리로, 좌표→주소 결과의 **건물명**을 먼저 보여 준다(내 위치일 때 "여기가 어디인지" 알기 쉽다).

### 6-19. 역 화장실이 데이터에 없는 이유 (2026-09-24 확인)
"역인데 화장실이 없다는 게 이해가 안 된다"는 지적을 데이터로 확인했다.
- 앱에 실린 **역 화장실은 1,052곳**(서울 372 · 경기 167 · 부산 108 · 인천 89 · 대구 79 …). 전국 지하철역·기차역 수에 크게 못 미친다.
- **같은 도시 안에서도 제각각**이다. 대구는 상인역·중앙로역·안지랑역 등 79곳이 등록돼 있지만 **동대구역·안심역은 없다**. 기차역도 서대전역·부산역·서울역은 있고 동대구역은 없다.
- 이유: 역 화장실은 **운영기관(코레일·도시철도공사)이 관리**한다. 지자체가 만드는 공중화장실 대장에 넣는 곳도 있고 안 넣는 곳도 있다 → **등록 여부가 기관 정책에 달렸다.**
- 조치: 역·터미널을 검색했는데 없으면 **그 사정을 그대로 말한다** — "역·터미널 화장실은 운영기관이 관리해 목록에서 빠지는 일이 잦습니다. 역 안에는 대개 화장실이 있으니 역 안내도를 봐 주세요."
- **다음 자산 후보**: 한국철도공사·서울교통공사 등 운영기관의 역사 화장실 데이터를 공공데이터포털에서 찾아 **합치면 이 구멍이 메워진다**(카탈로그에 후보로 등록).

### 6-20. 2단계 ③ 지도로 보기 (2026-09-24)
목록과 **같은 결과**를 지도에 놓는다(`app/mapview.js`). 목록 머리의 `🗺 지도` ↔ 지도 머리의 `☰ 목록`으로 오간다.

| 부분 | 만든 방식 |
|---|---|
| 핀 | `CustomOverlay` + 우리 CSS — **공중=청록 채움 · 개방=청록 테두리**(알약과 같은 규칙), 같은 자리는 **숫자**, 지금 닫힌 곳은 흐리게, 고른 핀은 1.25배 |
| 아래 카드 | 좌우로 넘기는 띠(`scroll-snap`). **카드 ↔ 핀 연동** — 핀을 누르면 카드가 그리로, 카드를 넘기면 지도가 그리로 |
| 기준 위치 | 파란 점. 오른쪽 `◎` 단추로 되돌아온다 |
| 다시 찾기 | 지도를 **사용자가** 옮겼을 때만 `이 지역에서 다시 찾기`가 뜬다 → 누르면 그 자리 주소(건물명 우선)로 기준을 옮겨 다시 찾는다 |

- **확대 수준은 반경으로 정한다**(사용자 지적: "너무 작게 보인다"). 처음엔 모든 핀을 담는 자동 맞춤(`setBounds`)을 썼는데 **멀리 있는 한 곳 때문에 레벨 7까지 멀어져** 핀이 작아졌다. 억지로 당겼더니(`setLevel(5)`) 이번엔 **핀이 화면 밖으로 밀려 카카오가 DOM에서 지워 버렸다**(핀 0개). → 기준점을 가운데 두고 **반경 → 레벨**(300m=3 · 500m=4 · 1km=5 · 2km=6)로 정한다. 500m 기준 레벨 7 → **4**.
- **고른 핀에 이름표**: `중앙로역(1호선) 209m`가 핀 위에 뜬다(선택된 것만 — 모두 띄우면 도심에서 겹친다).
- **이모지를 전부 SVG로 바꿨다**: `🗺`·`🏠`가 사용자 화면에서 깨져 보였다 → 머리 단추(지도·목록·집)뿐 아니라 **⚙ 보기 설정 · 🚻 검색 결과의 화장실 · 📍 기준 위치**까지 모두 직접 그린 아이콘으로. 이제 앱에 이모지가 하나도 없다(검사로 확인). `지도로 보기`는 주 색 테두리로 눈에 띄게.
- 교훈: **이모지는 글꼴이다.** 기기·OS·글꼴에 따라 모양·굵기·색이 달라지고 어떤 기기에서는 네모로 나온다. 아이콘은 우리가 그려서 색·크기를 지배한다(`.ic{width:1em}`으로 글자 크기 설정도 따라간다).
- **함정**: 우리가 지도를 움직이는 경우(처음 범위 맞추기·카드 넘김·기준으로 되돌리기)에도 `dragend`·`zoom_changed`가 떠서 "다시 찾기"가 계속 보였다 → `ignoreMove` 플래그로 **우리가 옮긴 것과 사용자가 옮긴 것**을 가른다.
- 어두운 모드에서 두 번째 지도(`#map2`)에 밝기 낮춤이 빠져 있었다 → 규약대로 함께 적용.
- 확인: 서울시청 500m 8묶음 · 핀 8개 · 카드 8장, 핀 누름 → 카드 이동, `다시 찾기` → 동국대학교 근처 5묶음으로 갱신(기준 이름도 건물명으로).

### 6-21. 변기 아이콘과 앱 아이콘 (2026-09-24 사용자 결정 B안)

| 시안 | 결과 |
|---|---|

### 6-23. 3단계 ① 거르기·알아보기·오프라인 (2026-09-25)

**거르기(필터)** — 칩 세 줄. ①`지금 열림`+반경(300·500·1km) ②`안심`(비상벨 20,246곳)·`장애인`(24,544)·`기저귀`(9,399)·`어린이`(4,539) ③시설 종류 17가지(`모든 종류`·공원 7,281·관공서 9,324·공공시설 9,732 …).

**알아보기 화면** — 첫 화면 아래 링크와 목록 맨 아래에서 들어간다. 담은 것: 이 앱은 무엇인가 · 보여 주는 것(공중·개방·간이·이동)과 **보여 주지 않는 것과 그 이유** · 그림 뜻(범례) · 시간 표시 5가지 · 위치 정확도 3단계 · **데이터의 한계**(역·민간 건물·오래된 정보·구글/네이버 링크 한계) · **위치는 저장하지 않는다** · 정보가 틀렸을 때. 수치(51,793곳·기준일)는 데이터에서 읽어 채운다.

**오프라인(`app/sw.js`)** — 한 번 본 것은 인터넷이 없어도 열린다.
- 화면 파일 17개는 설치할 때 저장, **지도 칸은 본 것만** 쌓되 **80개까지**(용량 폭주 방지).

### 6-24. 역사 화장실은 합치지 않고 잇는다 (2026-09-25 사용자 결정, v2 설계)
철도 데이터 24개(2,522행)를 확보한 뒤 **본 데이터에 합칠지** 정했다. 결론은 **합치지 않고 잇기**. 근거(사용자 제시):
- **원천 주체가 다르다** — 행안부·지자체 vs 코레일·교통공사. 합치면 **오류 신고처·연락처가 혼선**된다.
- **갱신 주기가 다르다** — 주 1회 vs 반기. 합치면 매주 가짜 변경이 생긴다.
- **표준화하면 정보가 버려진다** — 역층·게이트내외·출구번호·상세위치는 우리 스키마에 자리가 없다.
- **역 데이터만 떼어 쓸 일이 있다**(교통 접근성 분석 등).
→ 일반 원칙으로 승격: [데이터자산-규약 4-1](../../공통지식/데이터자산-규약.md) "합칠까, 이을까".

**설계(v2에서 구현)**
```
app/data/t/<칸>.json   본 데이터(행안부, 주 1회)        그대로
app/data/rail.json     역 데이터(철도공단·서울교통공사, 반기)  새로
```
- **표준화는 잇는 데 필요한 키까지만**: 역명(정규화)·노선·운영기관·좌표·출처·기준일. 나머지는 원래 모양 그대로.
- **화면에서 출처를 섞지 않는다**(사용자 지시): 겹치는 역이면 **`안심역 [국가철도공단]`처럼 출처를 붙인 별도 상자**로 보여 주고, 누르면 **그 출처의 값만** 상세로 — 역층 · **개찰구 안/밖** · 출구 번호 · 상세위치 · (서울교통공사는 변기 수·비상벨·CCTV까지).
- **신고 경로도 출처를 따라간다** — 역사 상자는 운영기관, 본 데이터 카드는 지자체.
- 겹침(역 753개 중 500개 추정)은 **표시만** 하고 양쪽 원본을 모두 둔다.

**이 방식이 주는 것**: 지금 이름으로 추측해 26곳만 표시하던 **개찰구 안/밖을 전국 역에** 정확히 붙일 수 있고(외 1,776 · 내 434), 비어 있던 **253개 역**이 채워진다. 합치기의 대가(정보 손실·주기 충돌·책임 혼선) 없이.

### 6-25. 역 좌표는 "역 하나에 점 하나" (2026-09-25 결정, v2 1단계)
합치지 않기로 한 뒤 남은 쟁점은 **좌표**였다(사용자 지적). 국가철도공단 파일 23개에는 좌표가 없다.

**결론: 역 안에서는 좌표 정밀도가 쓸모없다.** 지하 2층인지, 개찰구 안인지, 3번 출구 쪽인지가 훨씬 유용하다.
- 지도에는 **역마다 점 하나** — `안심역 [국가철도공단] · 역사 안 4곳`

**먼저 만들 것: 역 좌표표(station master)** — 역 833개에 대해 `역명 · 노선 · 운영기관 · 좌표 · 좌표출처 · 등급`. 화장실 2,210행은 여기에 붙기만 하면 되고, 나중에 교통 접근성 분석에도 재사용된다.

**교차역은 노선별로 따로 둔다**(사용자 지적). 좌표표의 단위는 **운영기관 → 노선 → 역명**이고 중복 제거 기준에도 선명이 들어 있어, 반월당(대구 1호선 2곳 / 2호선 4곳)·서울역(코레일 경의중앙 / 서울교통공사 1호선 / 4호선)은 합쳐지지 않는다. 노선이 둘 이상인 역은 **45개**.
- **예외 하나**: 노선만 다르고 **자리(층·개찰구·출구·상세위치)가 완전히 같은** 행이 **3곳(6행)** 있다 — 안산·정왕·중앙(수인분당 ↔ 4호선, 코레일). 한 역사를 두 노선이 함께 쓰는 곳이다 → **한 번만 보여 주고 노선을 함께 적는다.**
- 규칙: **노선이 다르면 다른 화장실이다. 자리까지 같을 때만 같은 화장실이다.**

### 6-28. 하단 메뉴 넷과 "저장" 규칙의 예외 (2026-09-25 결정)
**탭 넷** — 가까운 곳 · 저장한 곳 · 최근 본 곳 · 알아보기. 첫 화면(인트로)에는 두지 않는다.
- **지도는 탭으로 빼지 않는다** — 이미 목록 위 토글이라 들어가는 문이 두 개가 된다.
- **미리 받아 두기(오프라인)는 알아보기 안**에 둔다. 역 화장실을 넣는 지금 값이 가장 크다 — **지하 B1~B3에서 신호가 약한데 정작 그때 이 앱이 필요하다.**
- 공유·평점·후기는 넣지 않는다(쓰는 사람이 적으면 빈 화면만 보여 준다).

**규칙 하나가 바뀐다.** 지금까지는 `localStorage`에 **설정만** 저장하고 "위치는 저장하지 않는다"를 화면에 밝혀 왔다. 저장한 곳·최근 본 곳은 그 예외다.
- 조건: **이 기기 안에만** 둔다(서버로 보내지 않는다) · **한 번에 지울 수 있다** · 화면에 그렇게 밝힌다.
- 문구도 바꾼다: "위치는 저장하지 않습니다" → **"저장한 곳·최근 본 곳은 이 휴대폰 안에만 남고, 언제든 지울 수 있습니다. 서버로 보내지 않습니다."**
- 원칙은 그대로다 — **우리가 모으지 않는다.** 바뀐 것은 "사용자가 스스로 저장한 것은 기기에 둘 수 있다"는 예외뿐이다.

### 6-29. 노선마다 좌표를 따로 찾았다 — 그리고 "빈자리면 개명" 추측이 틀렸다 (2026-09-25)
사용자 지적에서 시작했다: *"교차역은 노선별로 위치가 같거나 다를 수 있다. `0호선 000역`으로 조회해야 하지 않나."* **맞았다.**

카카오에 `지역 + 노선 + 역명`으로 물으니 노선마다 다른 자리를 준다. 환승역 45곳을 재니 **300m 초과 3곳**(서울역 1↔4호선 **332m** · 노원 4↔7호선 326m · 동대문역사문화공원 306m), 100m 초과는 절반이 넘었다. 역 단위로 한 점만 썼다면 **서울역에서 300m 떨어진 출입구**로 보냈을 것이다. → 좌표 단위를 **기관 × 노선 × 역**으로 바꿨다(833행 중 **노선으로 찾은 것 816**).

**세 가지 함정을 만났다.**
1. **카카오는 그 노선에 그 역이 없으면 이웃 역을 준다** — 을지로3가 3호선 → 충무로역, 동구청 → 동대구역, 수성못 → 황금역. → 돌아온 **이름이 역명을 품는지 반드시 확인**한다.
2. **"이름이 달라도 아무도 안 쓴 자리면 개명으로 보자"는 추측은 틀렸다.** 그럴듯했지만 실제로는 **이웃 역 10쌍**(동구청=동대구·서문시장=청라언덕·수성못=황금·부전=서면·디지털미디어시티=수색 …)을 같은 자리로 붙였다. 되돌리고, 개명은 **확인한 것만 표로** 다룬다(`RENAMED`: 당고개→불암산 · 뚝섬유원지→자양 · 가정→가정중앙시장 — 셋 다 새 이름 역과 **0m**임을 확인).
3. **출처마다 역 이름 표기가 다르다** — 국가철도공단 `서울역`·`하남검단산역`, 서울교통공사 `서울`·`하남검단산`. 조인 키에서 **끝의 '역'까지 떼야** 같은 역이 두 줄이 되지 않는다(보여 줄 때는 원래 이름).

**합칠 기준을 수치로 정했다.** 같은 노선에서 이름이 다른 역끼리의 거리를 전부 재니 **500m 안에 붙은 쌍은 총신대입구 ↔ 이수(175m) 하나뿐**이고 그다음이 514m였다 → **300m 미만이면 같은 역**으로 합친다. 실제로 합쳐진 것은 그 한 쌍이다.

**비워 두었던 한 곳도 채웠다.** 인천2호선 **서구청**은 카카오가 `서해구청역`을 주는데 개명인지 확인이 안 돼 좌표를 비워 뒀었다. 사용자가 확인해 주었다 — **2026-07-01 인천 서구 분구(행정구역 개편)로 서해구청역이 되었다.** 개명표에 넣어 **833행 100%** 확보.
> 비워 두길 잘했다. 추측으로 채웠다면 맞았더라도 **왜 맞는지 모르는 값**이 남았을 것이고, 틀렸다면 조용히 틀린 채로 남았을 것이다. **모르면 비우고 표시한다 → 사람이 채운다.**

**검증(다시)**: 환승역 45곳 노선 간 **1km 초과 0** · 우리 데이터의 같은 지역 동명 역 672곳과 **중앙값 39m · 300m 이내 94%**.

**교훈 둘**
1. 그럴듯한 보정 규칙일수록 **무엇을 붙였는지 이름 쌍으로 찍어 봐야** 한다. 개수만 봤다면 "10곳이 합쳐졌다"를 성과로 읽었을 것이다.
2. **역은 잘 바뀌지 않지만 이름은 바뀐다**(사용자 지적). 시설·층·출구는 몇 년째 그대로여도 **역명은 행정구역 개편·시설 이전·명명권으로 바뀐다.** 이름으로 잇는 데이터는 **속성이 안 변해도 키는 흔들린다** → 갱신 주기를 "정보가 잘 안 바뀌니 길게"로 정하면 안 되고, **이름만이라도 연 1회 대조**해야 한다. 규약 [1-1 이름은 키가 아니다](../../공통지식/데이터자산-규약.md)로 올렸다.

### 6-30. 역 안 화장실을 앱에 붙였다 (2026-09-25)
`build_rail_app.py` → `app/data/rail.json` (**212KB · 역 833곳 · 화장실 966칸**). 본 데이터(타일 3,653개)와 **파일을 따로 두고 앱이 화면에서 잇는다.**

**출처를 고르는 규칙** — 섞지 않고 역마다 하나를 쓴다. 서울교통공사 파일이 있으면 그것(2026-02 · 칸 36개 · 변기 수·전화까지, **268역**), 없으면 국가철도공단(2025-06 · 칸 9개, **565역**). 같은 자리의 남자·여자 행은 한 칸으로 묶는다(원본은 남/여가 따로 한 행).

**화면에서 한 일**
- **연한 청록 상자 + 머리띠**("역 안 화장실 · 운영기관 제공 / 국가철도공단"). 색만으로 구분하지 않는다 — 출처 이름을 글자로 적는다.
- **거리순에 그대로 섞는다.** 반월당에서: 2호선 반월당역 39m → 1호선 반월당역 126m → 지자체 카드들.
- 카드 제목은 **`대구 1호선` 반월당역** — 노선이 다르면 다른 카드다(6-29).
- 층은 `B1`·`2F` 배지, 개찰구 안/밖은 색이 다른 알약, 출구는 `3번 출구`, 그리고 **상세위치 글**이 본문이다. 이 데이터의 값은 좌표가 아니라 **말로 하는 안내**다.
- **지도에도 올렸다.** 목록에 있는데 지도에 없으면 두 화면이 다른 말을 한다(T21) → 기차 아이콘의 청록 핀.
- **겹침은 표시만**: 같은 역이 지자체 목록에도 있으면 "이 역은 지자체 목록에도 있어요"만 적고 값은 섞지 않는다(규약 4-1).

**두 가지를 고쳐 잡았다.**
1. **"지금 열림만"이 역을 통째로 지웠다.** 국가철도공단에는 개방시간 칸이 없어 상태가 `unknown`이었고, 기본값인 "지금 열림만"에서 565역이 사라졌다 — 시간 1안("첫차~막차로 안내")을 **글자에만** 적용하고 **거르기에는 적용하지 않은** 탓이다. → 상태를 `likely`로 두고 05:00~24:00에는 통과시킨다. 글은 여전히 회색 "보통 첫차~막차"(단정하지 않는다).
2. **`.fl` 이름이 부딪혔다.** 층 배지에 쓰려던 클래스를 상세 화면 픽토그램의 이름표가 이미 쓰고 있었다 → `.flr`로 바꿨다. **새 화면을 붙일 때는 클래스 이름부터 검색한다.**

**검색 문구도 같이 고쳤다.** `동대구역`을 찾으면 이제 "역은 공공데이터에 없어요"가 아니라 **"동대구역의 화장실은 아래 `대구 1호선` 상자에 있어요"**가 나온다. 사용자가 처음 지적한 *"역인데 화장실이 없다는 게 이해 안 된다"*가 여기서 닫혔다.

### 6-31. 하단 메뉴 넷과 "기기 안에만" 저장 (2026-09-25)
`app/saved.js` — 탭 **가까운 곳 · 저장한 곳 · 최근 본 곳 · 알아보기**.

**탭을 어디에 둘지가 결정이었다.** 목록·저장·최근·알아보기에만 두고 **첫 화면·핀·검색·상세·지도에는 두지 않는다.** 상세와 지도는 '깊이 들어간 화면'이라 탭을 두면 돌아가는 길이 두 개가 되어 헷갈린다. 지도는 이미 목록 위 토글이라 탭으로 빼면 문이 두 개가 된다.

**규칙 하나가 바뀌었다** — "설정만 저장한다"에서 **"사용자가 스스로 담은 것은 기기에 둔다"**로. 조건 셋을 지켰다: ① 서버로 보내지 않는다 ② 화면마다 **한 번에 지우기** ③ 알아보기 문구를 고쳤다("위치는 저장하지 않습니다" → "저장한 곳·최근 본 곳은 이 휴대폰 안에만 남고, 언제든 지울 수 있습니다").
- 저장·최근은 **레코드를 통째로** 담는다(이름만 담으면 오프라인에서 다시 열 수 없다). 열쇠는 `t:번호` · `r:기관|노선|역` · `p:좌표`.
- 최근은 **20개**까지, 같은 것을 다시 보면 맨 위로. **검색으로 고른 자리도 담는다** — 같은 주소를 또 치지 않게.
- 저장이 막힌 기기(사생활 보호 모드·용량 부족)에서도 앱이 멈추지 않게 읽기·쓰기를 모두 감쌌다.

**미리 받아 두기(오프라인)는 알아보기 안**에 뒀다. 지금 자리 둘레 5×5칸을 받아 두면 서비스 워커가 저장한다 — 시험에서 **23칸**이 저장됐다. **지하 B1~B3에서 신호가 약한데 정작 그때 이 앱이 필요하다**는 것이 역 데이터를 넣으면서 분명해졌다.

**확인**: 탭바는 목록에만 뜨고 첫 화면·상세·지도에서는 사라진다 · 어두운 모드 + **가장 큰 글씨**에서 탭 높이 66px(44px 규칙 통과)·가로 스크롤 없음 · 저장한 역은 청록 줄, 지자체 화장실은 흰 줄로 구분된다.

### 6-32. 배포 전 점검 — 버그 다섯과 편의 일곱 (2026-09-25)
사용자가 육안 검수 전에 "기준대로 됐는지 꼼꼼히 보라"고 해서 한 바퀴 돌았다. **버그 다섯(T25~T29)**이 나왔고, 셋은 **새로 낸 길**에서 생겼다(하단 탭·역 데이터). 자세한 것은 버그이력.

**편의 일곱을 함께 넣었다.**
| 넣은 것 | 왜 |
|---|---|
| **「개찰구 밖만」 칩** | 역 화장실의 **80%가 개찰구 밖**이다. "표 없이 쓸 수 있나"는 급한 사람에게 결정적인데 카드마다 눈으로 봐야 했다 |
| 역 카드에 **길찾기·입구 보기** | 상세로 들어가야 했다. 급할 때 한 번의 탭이 크다 |
| **"같은 역이지만 노선이 달라"** 꼬리표 | 반월당 1·2호선이 나란히 뜨는 것을 중복으로 오해하지 않게 |
| 첫 화면 **저장한 자리 바로가기** | 위치를 잡기 전에도 집·회사로 바로 간다 |
| 지우기에 **한 번 더 묻기** | 되돌릴 수 없는데 20px 글자 링크였다 → 44px 단추 + 확인 |
| 지도 아래 카드에 **역 포함** | 목록에 있는데 지도 카드에 없었다(T26과 함께) |
| 검색 제안에 **역 직접 노출** | 역 이름으로 찾는 사람은 그 역에서 화장실을 찾는 사람이다 — 카카오 결과를 고른 *뒤*가 아니라 **치는 순간** 보여 준다 |

**문구를 「원천데이터 관리기관」으로 통일했다**(사용자 결정). 철도 데이터가 들어오면서 "지자체"가 **틀린 말**이 됐다.
- 상위어 **원천데이터 관리기관**, 구체어는 **지자체**(공중·개방) / **철도 운영기관**(역). 알아보기에 표로 넣고, 상세의 신고 안내도 출처를 따라가게 했다.
- 기준일이 둘이 됐다 → 목록 **머리글은 짧게**(좁은 화면에서 세 줄로 접혔다), 기준일 둘은 **목록 맨 아래와 알아보기**에 적는다.

**카카오톡·홈 화면 추가**(`app/mobile.js`)는 착한가격의 것을 옮겼다. 옮기며 둘을 바꿨다 — **이모지 대신 아이콘**(우리 규칙), **문구를 짧게 끊어** 좁은 화면에서 어중간하게 접히지 않게. 카카오톡 안에서는 **내 위치가 막히므로** 이 앱에서는 특히 크다.

### 6-33. 번호가 같아도 같은 화장실이 아니다 — 묘비 정책 (2026-09-25 결정)
갱신 리허설에서 잡힌 한 건에서 시작했다. `(주)가온`(김해 풍유동) → `(주)가온에너지 힘이나주유소`(김해 생림면), **관리번호는 그대로**, 핀은 **13,186m** 이동.

**사용자 지적이 문제의 핵심을 짚었다** — *"고유번호-관리번호를 조인해 놓고 그 정보는 안 바뀐다고 했는데, 번호 재사용이나 오기재 우려가 있다. 관리번호가 불변이라는 보장은 없다."* 모듈 5장은 **우리가** 번호를 재사용하지 않는다고만 적어 두었고, **원천이 지키지 않을 때**는 한 줄도 없었다.

**왜 위험한가 — 조용해서다.** 이 건은 변경 분류('기존·변경'), 좌표 등급(A), 주소 검증(정상)을 **모두 통과**했다. 삭제도 신규도 아니라 확인 목록에도 안 걸린다. 유일한 흔적이 좌표 이동이었고, 그 검사는 **그날 만든 것**이었다(T31).

**정한 것**
| | |
|---|---|
| **감지** | 이름·주소가 **함께** 바뀌고 좌표도 100m 넘게 움직이면 `swapped_ids.csv`로 뽑는다. 좌표 이동을 함께 보는 이유는 **행정구역 개편으로 주소 표기만 바뀌는 것**(광주 → 전남광주통합특별시)과 가르기 위해서다 |
| **제안** | 1km 넘게 움직였으면 `결정=다른 시설`을 기본값으로 채워 둔다. **자동 실행은 하지 않는다** — 번호 폐기는 되돌리기 어렵다 |
| **반영** | `--publish`에서 사람이 '다른 시설'로 둔 것만 **옛 번호 폐기 + 새 번호 발급**. 폐기 번호는 누구에게도 물려주지 않고 옛 이름·주소·사유·날짜를 남긴다 |

**구현하며 잡은 허점**: `retire()`를 같은 날 두 번 부르면 **방금 준 새 번호까지** 폐기됐다 → 관리번호+폐기일로 막았다(해가 바뀌어 또 재사용되는 일은 있을 수 있어 날짜까지 본다).

**빈도와 영향의 비대칭** — 53,588건 중 **1건(0.002%)**. 드물지만 **조용하고 되돌릴 수 없다.** 게다가 이번 주에 「저장한 곳」을 넣어 위험이 커졌다. 이런 것이 검사할 값이 있는 것이다.

**모듈로 올렸다**: 파이프라인 **5-1**(절차·임계값·묘비), 규약 **1-1**(이름은 키가 아니다 **· 번호도 영원하지 않다**), 배포 전 체크리스트(동일성 확인이 갱신에 들어 있는가). **착한가격도 같은 위험**이 있다 — 거기도 공식 업소번호를 같은 업소 판별의 1순위 키로 쓴다.

> **반대 방향도 있다**: 번호가 바뀌었는데 같은 대상인 경우는 '삭제+신규 짝'이 다룬다. **번호와 대상은 어느 쪽으로든 어긋난다.**

### 6-34. 역은 없어지지 않는다 — 그 성질을 검사로 썼다 (2026-09-25)
사용자 지적에서 시작했다: *"역은 화장실·가게와 다르다. 노선이 연장되어 역이 추가될 수는 있어도 **기존 역이 없어지지는 않는다.** 따라서 어떤 노선에서 기존 역명이 사라지면 확인이 필요하고, 동시에 새 역명이 나타나면 바뀐 것으로 추정할 수 있다."*

**이건 데이터의 성질을 그대로 검사로 바꾼 것이다.** 화장실은 폐쇄되고 가게는 문을 닫지만, 역은 그렇지 않다. 그래서 **"사라졌다"는 사실 자체가 오류 신호**가 된다 — 다른 데이터에서는 정상인 일이 역에서는 비정상이다.

**넣은 검사**(`build_rail.py compare_prev`) — 지난 판을 덮어쓰기 전에 견준다.
| 결과 | 뜻 |
|---|---|
| 사라진 역 + 같은 노선에 새 역, **300m 이내** | **개명**(거의 확실) |
| 사라진 역 + 같은 노선에 새 역, 멀리 | 개명? (사람이 확인) |
| 사라진 역 + **짝 없음** | **확인 필요** — 원본 누락이거나 우리 처리 오류다 |
- 짝은 **일대일**로 맞춘다(가까운 쌍부터). 처음엔 한 새 역이 사라진 역 여럿의 짝으로 잡혀, **진짜 누락된 역이 "개명?"에 묻혔다.**
- 추정은 여기까지다. 개명표(`RENAMED`)에 넣는 것은 사람이 확인한 뒤.
- 시험: 서해구청을 옛 이름으로 되돌리고 가짜 역 하나를 넣었더니 → `서구청 → 서해구청 0m · 개명` / `있을리없는역 → (없음) · 확인 필요`로 정확히 갈렸다.

**앱까지 이었다.** `rail.json`에 개명표를 싣고, **저장한 역**이 지금 자료에 없으면 세 가지로 갈라 보여 준다.
| 그대로 있음 | 개명됨 | 사라짐 |
|---|---|---|
| 평소대로 | 새 이름으로 **바꿔서** 보여 주고 *"당고개역에서 불암산역으로 이름이 바뀌었어요"* · 누르면 새 역이 열린다 | *"지금 자료에 이 역이 없어요 — 이름이 바뀌었는지 확인이 필요합니다"* |

**화장실의 묘비(6-33)와 짝이다.** 화장실은 번호가 키라 **번호 재사용**을 의심하고, 역은 이름이 키라 **개명**을 의심한다. 둘 다 *"키가 같다고 같은 대상이 아니고, 키가 사라졌다고 대상이 사라진 것도 아니다"*라는 한 가지 이야기다.

### 6-35. 비공개 백업 — 354MB를 31MB로 (2026-09-25)
**먼저 드러난 사실**: 화장실 백업은 2026-09-23 커밋 하나가 **로컬에만** 있었다(원격 저장소 없음). **같은 컴퓨터 안에만 있으면 백업이 아니다.**

**배포보다 백업이 먼저인 이유** — 배포는 되돌릴 수 있고 **데이터 분실은 되돌릴 수 없다.** 게다가 배포하는 순간 번호 대장의 무게가 달라진다(사용자가 링크를 공유·저장하기 시작하면, 대장을 잃는 순간 **그 링크가 전부 무효**가 된다).

**GitHub 한도를 수치로 확인했다**: 파일 하나 **100MB 차단**(하드) · 저장소 1GB 권장·5GB 강력 권장(소프트) · push 한 번 2GB. 그리고 **git은 과거를 지우지 않아 누적된다** — 파일을 나중에 지워도 저장소는 줄지 않는다.

**세 갈래로 나눴다.**
| 갈래 | 무엇 | 주기 |
|---|---|---|
| 핵심 | 번호 대장·수기 보정·사전·골든 표본·역 좌표표 | 매번 |
| 압축 | 기준본(`.gz`) · 수집 원본 json(`.gz`) | 매번 |
| 캐시 | 카카오·주소·네이버(`.gz`) | **월 1회** |

**담지 않기로 한 것** — 같은 내용이 이미 있는 것들. `data/raw/toilets_*.csv`는 기준본의 `toilets_raw.csv`와 **바이트까지 같았고**(md5 일치), 제안 폴더의 큰 CSV도 마찬가지다. 중간 산출물(`toilets_geo.csv`·`toilets_addr.csv` 79MB)은 원본+캐시로 다시 만들 수 있다.

| | 전 | 후 |
|---|---|---|
| 작업 폴더 | 354MB | **31MB** |
| 가장 큰 파일 | 71MB(카카오 캐시) | **6.8MB**(그 압축본) |

**압축은 100MB 한도를 피하려는 것이지 저장소를 줄이려는 것이 아니다.** git은 이미 내부적으로 압축해 저장하고, 오히려 `.gz`는 조금만 바뀌어도 파일 전체가 달라져 델타 압축이 안 먹는다. 그래서 **캐시는 월 1회**로 낮췄다.

**만들면서 버그를 하나 냈고, 확인하다 잡았다.** "담을 목록에 없는 파일은 지운다"를 넣었는데, 캐시를 건너뛴 회차에 `want` 목록에서 캐시가 빠져 **백업이 캐시 압축본을 통째로 지웠다.** API 13만 회를 날릴 뻔했다 → 캐시 경로는 **이번에 담지 않아도 목록에 남기도록** 고쳤다.
> 교훈: **백업의 값은 "되살릴 수 있는가"로만 증명된다.** 담은 직후 풀어 봤다 — 카카오 79,335건·주소 51,337건·기준본 53,649행·원본 53,588건, 대장 53,582개 확인.

**기록도 정리했다.** 한 번도 push하지 않았으므로 `.git`을 지우고 **첫 커밋부터 다시** 만들었다(옛 기록에 남은 큰 파일 71MB가 영원히 따라다니지 않게). **push 전이 유일한 기회였다.**

**앞으로 늘어나는 양**: 기준본 압축본이 주당 약 6.5MB, 캐시가 월 약 11MB → **연 400~500MB**. 1~2년 뒤 권장선(1GB)에 닿으므로, 그때 기준본 백업을 월 1개로 낮추는 것을 검토한다.

### 6-36. 외부 링크를 전부 눌러 봤다 (2026-09-25)
배포 전 체크리스트의 마지막 항목. **둘 다 실제로 눌러 봐야만 나오는 것이었다.**

**① 카카오 길찾기는 도보가 아니었다.** 우리 화면은 「길찾기 **(도보)**」라고 적고 카카오를 주 버튼으로 뒀는데, 열어 보니 PC는 `target=car`, 휴대폰은 `applink…&by=car` — **자동차 경로**였다. 화장실은 대개 수백 m라 자동차 경로는 뜻이 없다.

**② 링크 점검 방법 자체가 틀렸다.** 시군구 홈페이지 219곳을 **병렬 12**로 확인했더니 **96곳 실패**로 나왔다. 대구 8곳이 전부 실패였는데, 브라우저로 열어 보니 멀쩡했다.

|---|---|

**무료 쿼터는 계정당 한 앱뿐이었다.** 나누면 분리되는 게 아니라 **한쪽이 유료**가 된다. 내 권고대로 갔으면 비영리 앱에 결제 수단을 연결할 뻔했다. → 되돌려 **착한가격지도 앱의 JS 키를 함께 쓰고**, 그 키에 `your-toilet.pages.dev`를 나란히 등록했다. 왜 한 앱을 쓰는지 `index.html` 주석으로 남겨 다음에 또 나누자고 하지 않게 했다.

**진단에서 얻은 것**: 지도가 안 뜰 때 브라우저는 "스크립트 로드 실패"만 말한다. **curl로 SDK를 직접 받아 보니** 원인이 한 줄로 나왔다 — `NotAuthorizedError: App(너의 화장실은) disabled OPEN_MAP_AND_LOCAL service.` 도메인 문제로 착각하기 딱 좋은 상황이었다. **외부 서비스가 막을 때는 그 서비스의 응답을 직접 읽는다.**

**교훈**: 플랫폼의 요금·한도 구조는 **문서가 아니라 그 화면에서 확정된다.** 내 권고는 그럴듯했지만 실제 제약을 몰랐다. 되돌릴 수 있는 시점(사용자 0명)에 부딪힌 것이 다행이다.

### 6-38. 역 카드에서 버튼을 도로 뺐다 (2026-09-25, 배포 후 사용자 지적)
배포한 앱을 쓰시던 사용자 지적: *"취지는 이해되지만 시인성이 — 다른 것과 함께 있으면 복잡해진다. 다른 것과 동일하게 길찾기를 조정하면 좋겠다."*

**내가 6-32에서 넣은 것을 되돌렸다.** 그때 근거는 *"상세로 들어가야 한다 — 급할 때 한 번의 탭이 크다"*였다. 틀린 근거는 아니지만 **거래가 손해였다**:
- 목록에서 **역 카드만** 단추 두 개를 달고 있었다. 역 카드는 이미 머리띠 + 노선 + 층 행 여러 개 + 시간 + 안내 상자로 가장 무거운데, 거기에 단추까지 붙으니 **거리순으로 섞였을 때 혼자 도드라졌다.**
- 우리는 *"먼저 거리, 그다음 성격"*으로 정해 놓고(6-27), **화면은 그 차례를 뒤집고 있었다.**
- 아낀 것은 탭 **한 번**뿐이었다. 카드를 누르면 어차피 같은 단추가 있는 상세로 간다.

**한 일**
1. 목록의 역 카드에서 `길찾기`·`입구 보기` 제거 → 지자체 카드와 똑같이 **누르면 상세**로만.
2. 대신 **상세에서 「길찾기」를 「역 안 어디에」 위로** 올렸다. 화장실이 여러 칸인 역(반월당 2호선 2곳)에서 스크롤해야 보이던 것을 위로 당겨, 목록에서 단추를 뺀 몫을 갚았다.
3. **예외 처리도 걷어냈다.** 누를 수 있는 카드 안에 누를 수 있는 단추가 있어 `data-stop`으로 잘못 눌림을 막고 있었는데, 단추가 없어지니 그 예외도 필요 없다. **예외는 남겨 두면 나중에 버그가 된다.**

**교훈**: *"한 번 덜 누르게 한다"*는 이유는 거의 항상 그럴듯하다. 그런데 **그 대가로 목록 전체가 읽기 어려워지면 손해다.** 편의 기능은 **그 화면 하나가 아니라 섞여 있는 화면에서** 판단해야 한다 — 역 카드만 따로 보면 단추가 있는 쪽이 분명히 나아 보였다.

### 6-39. 행정구역 개편을 앱까지 반영했다 — 이름에서 코드로 (2026-09-26)
장학금 세션이 발견해 넘겨준 일: 인천 개편(2026-06-30)으로 생긴 **영종구·서해구·검단구** 화장실이 오류 신고에서 **구청을 못 찾는다.**

**파 보니 구멍이 더 컸다.** 특례시 13곳과 서울 강남구도 처음부터 안내가 없었다 — 합쳐 **7,409장(14.7%)**. 원인은 하나였다: **시군구를 주소 이름의 다수결로 정한 것.**
| 왜 깨지나 | 예 |
|---|---|
| 이름이 바뀌면 옛·새 이름이 섞여 80%를 못 넘는다 | 영종 52% · 서해 78% · 검단 66% → **빈칸** |
| 특례시는 `수원시 팔달구`로 **두 마디** | 앞 마디만 읽어 `수원시` → 코드표엔 일반구만 → **빈칸** |
빈칸이면 `build_gov_links.py`가 구청을 **수집조차 하지 않았고**, 앱은 주소 글자로 이름을 찾으니 개편된 구는 영영 못 찾았다. **옛 중구는 제물포구·영종구로 갈려 이름으로는 가를 수조차 없다.**

**고친 방식 — 이름 대신 코드.**
1. `build_sgg_codes.py`: **자치단체코드 → 법정동 시군구코드**(228/228). 원본의 `개방자치단체코드`는 **관리 지자체**라 주소가 옛 이름이어도 **이미 새 구로 갈려 있었다**(34910 영종 · 35010 제물포 · 35610 서해 · 35650 검단). 증거는 주소 캐시의 법정동코드(227곳) → 없으면 **현재 이름과만** 맞추기(1곳).
2. 카드에 **`sgg`** 칸을 붙이고(`build_app_data.py`), `gov_sites.json`을 **시군구코드 키**로 바꿨다. 인천 새 구청 4곳·특례시 14곳을 공식 누리집을 **제목으로 확인해** 더하고, 일반구 39곳은 **모시(시청)**로 이었다.
3. 앱은 코드로 찾되 **시도까지 어긋나면 주소를 따른다.** 목포·부산·영천 화장실이 **양산시 소관**으로 적힌 행이 3곳 있었다 — 코드를 곧이곧대로 믿으면 다른 시도 기관을 안내하게 된다.
4. 목록을 **공통지식 기준자료**(`시군구_누리집.json`, 267곳)로 올려 세 프로젝트가 같은 것을 본다. 앱은 만들 때 거기서 가져온다.

**결과**: **50,544장 전부** 구청을 찾는다. 옛 중구 → 영종구청 45·제물포구청 38, 옛 서구 → 서해구청 46·검단구청 17. 브라우저로 영종·서해·검단·옛 중구·수원 팔달구 표본을 열어 **실제 누리집이 열리는 것**까지 확인했다.

**덤으로 잡은 것**: 옛 목록의 시도 단위 항목 3개가 **엉뚱한 식당 인스타그램**이었다(네이버 지역검색이 시청 근처 가게를 집음). 이름 매칭에서는 한 번도 쓰이지 않아 드러나지 않았다.

**확인하다 또 T23을 만났다.** 고친 것이 화면에 안 나와 함수를 의심했는데, 브라우저가 **옛 `index.html`**을 쓰고 있었다. 게다가 우리 서비스워커는 `/`를 **쿼리를 무시하고** 맞히므로 `?fresh=...`로도 안 뚫린다. → 확인 전에 **로드된 파일의 해시부터** 본다(`script[src^="detail.js"]`).

**교훈**: **규약 1-1(이름은 키가 아니다)은 데이터에서 끝나지 않는다.** 데이터를 코드로 이어 놓아도 **화면에서 다시 이름으로 찾으면** 같은 자리에서 또 깨진다. 그리고 **다수결로 정한 값은 경계에서 조용히 빈칸이 된다** — 빈칸을 실패로 세지 않으면 아무도 모른다.
