## 상세

### T1. curl 한글 검색어 깨짐
- 증상: Windows Git Bash의 curl로 도로명주소 API를 부르자 결과가 0건이거나 엉뚱(숫자만 일치). 처음에는 "API가 줄임말을 못 읽는다"고 잘못 보고했다.
- 원인: 명령줄 한글 인코딩. Python `requests`로는 줄임말·띄어쓰기 없음·옛 이름 모두 정상 처리.
- 회귀 확인: 시험 호출은 스크립트와 같은 경로(Python)로.

### T2. 첫 번째 결과 채택
- 증상: `금산군 복수면 곡남리`(후보 264건), `대전광역시 서구`(24,966건)도 '정상'이 될 뻔함. 착한가격 `addr_util.py`는 번지까지 있는 가게 주소라 문제가 안 드러났다.
- 해결: 후보가 모두 같은 건물이거나 주소 끝(도로명+번호, 동·리+번지)이 정확히 같을 때만 채택, 아니면 '모호'. 자치단체코드로 얻은 시도·시군구 밖 결과는 '지역불일치'. 400곳 시험 모호 16 → 4.

### T3. 카카오가 못 읽는 주소 형식
- 해결: 번지·호 → `N-M`, 동·리에 붙은 번지 띄우기, 도로명에 붙은 건물번호 띄우기(`473번길`은 그대로), 층 범위 제거. 좌표 실패 791 → 569.
- 남은 실패는 도로명주소·카카오 모두 없는 주소(원천 오류).

### T4. 산지 핀 옮기기
- 근거: 300m 넘게 떨어진 126곳 중 이름이 거의 같아도 봉우리·골짜기 자체(`국사봉`, `고산골`), 엉뚱한 곳(면사무소·식당·여관 27곳).
- 원칙: 교차 확인용 장소검색도 검증 없이 좌표를 덮어쓰지 않는다.

### T5. 캠퍼스 건물 좌표 오답
- 증상: `태백중학교(행정동 2층)` → `태백중교`(693m), `한강시민공원(자연학습장)` → 공원 주차장, 공항 탑승구 → 주차장.
- 해결: 묶음 안에서 이 화장실을 가르는 말(공통 앞부분·층·방향 제외)이 장소명에 있어야 채택. 주차장·충전소 등은 그 말이 이름에 있을 때만. `야외`·`실내`·`고객` 등은 가르는 말로 안 씀. 2,070 → 1,023곳(표본 20곳 중 약 19곳 맞음).

### T6. history_v2 100행 제한
- 증상: `numOfRows=1000`을 줘도 100행만 와서, 첫 쪽만 본 비교가 틀림.
- 해결: 쪽 끝까지(`totalCount`까지) 받기. `info_v2`는 1,000행 가능.

### T7. 요일 말 부분 일치
- 해결: 요일 말을 긴 것부터 대조하는 정규식, `토`·`일` 한 글자는 `(토)`·`일)`처럼 괄호와 함께만. 시험: `test_hours.py`.

### T8. 옛 지번으로 조용히 찾아짐
- 증상: 가짜 다음 판 시험에서 도로명만 바꾸자, 도로명이 지역 밖으로 거부되고 바뀌지 않은 지번으로 옛 위치를 찾음.
- 해결: `update.py`에서 '도로명 지역불일치·주소없음 → 지번으로 찾음'은 `확인필요`로 표시하고 확인 목록(`new_bad_coords.csv`)에 넣는다.
- 회귀 확인: 같은 지자체 안 이전(도로명·지번 모두 바뀜)은 좌표가 바뀌고, 도로명만 엉뚱하면 확인 목록에 오른다.

### T9. 같은 건물을 캠퍼스로 판정
- 원인: 이름들의 공통 앞부분이 `별내도서관지`가 되어 `지하`·`지상`이 반으로 잘리고 `하`·`상`이 남아 "이름이 서로 다름"으로 판정. 먼저 넣은 `지상` 규칙이 효과가 없던 이유도 이것.
- 해결: `campus_coords.kind` — 이름마다 층·방향 말을 뺀 뒤 같은 이름이 70% 이상이면 같은 건물. 같은 건물 173 → 232묶음(887 → 1,198곳), 넓은 곳 W 5,083 → 4,822.
- 회귀 확인: 별내도서관(같은 건물), 스타필드하남(같은 건물), 부산시민공원·부경대학교(캠퍼스·단지).

### T10. 칸 경계 반올림
- 원인: 칸은 원래 좌표로 정하고 파일에는 소수 5자리로 반올림한 좌표를 저장 → 경계 바로 옆 19곳이 옆 칸 좌표가 됨.
- 해결: 반올림한 값으로 칸도 정함. `check_data.py`의 "좌표가 자기 칸 안" 검사가 잡았다(검사 규칙이 첫 실행에서 실제 버그를 찾은 사례).

### T11. 쉼표가 든 행정동
- 원인: `clean`이 쉼표 뒤를 "나머지 주소"로 보고 잘랐다. 행정동 이름(`중계2,3동`, `상계6,7동`)에는 쉼표가 들어간다. 잘린 `중계2`를 카카오가 `중계동 2번지`로 찾아 필지(B) 등급을 받았다.
- 해결: 쉼표 행정동 + 번지면 법정동 이름으로 바꾼다(`중계2,3동514-4` → `중계동 514-4`). 21곳. 같은 원리로 필지 좌표의 번지가 원본 지번과 다르면(23곳) 카카오·네이버 장소가 일치할 때만 옮기고 아니면 숨김.
- 교훈: 공통 규칙("쉼표 뒤는 버린다")이 한국 주소의 예외(행정동 이름)를 깨뜨린다 — 정밀 점검의 "주소가 제각각인데 같은 좌표" 검사로 찾았다.

### T12. 도로명·지번 어긋남
- 규모: 도로명·지번이 모두 있는 31,393곳 중 1,531곳이 300m 넘게 어긋남(처음 "동 이름이 다른 곳"만 세어 323으로 과소 추정).
- 방향이 제각각: 도로명 칸에 관청 주소(부산 동구청 `구청로 1` + 시설명) / 지번 칸에 본국 주소(`화순이서우체국`의 지번이 화순우체국).
- 첫 규칙("단서 없으면 숨김")은 705곳을 숨겨 `2호선 잠실역`, `강남터미널지하상가`까지 사라짐 → 네이버 교차 확인(A등급 90%가 150m 안)을 근거로 단서 없으면 도로명 유지 + 확인 목록, 도로명을 3곳 이상이 같이 쓰면(관청·대표 주소) 지번.
- 결과: 도로명 유지 626 + 확인 목록 409, 지번으로 옮김 491, 숨김 5(카카오·네이버가 서로 다른 쪽).
- 후속(2026-09-23): 남은 확인 목록은 **시설 이름 기준**(사례지식 2-11)으로 다시 풀어 409 → 276.
- 교훈: 숨김 규칙도 숫자로 영향을 본다 — "확실하지 않으면 숨김"이 도심 핵심 시설을 지우면 원칙의 목적(믿을 수 있는 안내)에 어긋난다.

### T13. 일요일 미운영
- `휴관·휴무·휴일·미개방·폐쇄·제외`만 쉬는 날 말로 알아서 `미운영`을 놓침. 정밀 점검의 "폐쇄 말" 표본에서 발견.

### T14. 자정 마감이 "0시까지"
- 증상: 1단계 앱 첫 실행에서 `시청역(1) 화장실`(05:30~24:00)이 `0시까지`로 보임. 계산은 맞고 **표기만 틀림**(24시를 24로 나눈 나머지 0).
- 해결: 0시는 `자정까지`로 적는다(`app.js` `statePill`).
- 교훈: 계산 시험(`test_hours.py` 57항목, `test_hours_js.py` 5,288건)이 모두 통과해도 **화면 글자는 눈으로 봐야 한다** — 시험은 값이 같은지만 보고, 사람이 읽는 말은 보지 않는다.

### T15. 다시 만들 때 공휴일 목록이 사라짐
- 증상: `build_app_data.py`를 다시 돌린 뒤 `app/data/holidays.json`이 없어져, 앱이 공휴일을 하나도 모르는 상태가 됐다. 화면에는 아무 오류도 나지 않는다(받기 실패를 빈 목록으로 넘김) — **조용한 고장**.
- 원인: 출력 폴더를 `shutil.rmtree(OUT)`로 통째로 지웠다. 그 폴더에는 1년에 한 번 받는 공휴일 목록도 같이 있었다.
- 해결: 칸 폴더(`app/data/t`)만 지운다. 그리고 `check_data.py`에 **공휴일 목록이 있고 올해가 들어 있는지** 검사를 넣어 배포 전에 걸리게 했다.
- 교훈: "다시 만들면 되는 것"과 "따로 받아 둔 것"을 같은 폴더에 두면 함께 지워진다 — 지우는 범위는 만드는 범위와 같아야 한다.

### T16. 한글 입력기와 Enter — 검색이 조용히 안 됨
- 증상(사용자 발견): 첫 화면 → "다른 곳"에서 주소나 건물 이름을 넣어도 목록이 뜨지 않았다. 오류도, 안내도 없다.
- 원인: 검색을 **Enter(form submit)로만** 받았다. 한글 입력기는 글자를 조립하는 동안 Enter를 "조립 확정"에 쓰기 때문에 그 Enter는 폼까지 오지 않는다. 자동 시험은 값을 직접 넣어(`form_input`) 통과했으므로 잡히지 않았다 — **입력기를 거치지 않는 시험은 한글 입력을 시험한 것이 아니다.**
- 해결: ① 눈에 보이는 **검색 버튼** ② 글자를 멈추면 350ms 뒤 **자동 검색**(조립 중에는 기다림) ③ `compositionend`에도 검색. 실패하면 이유를 적는다(지도 모듈 못 불러옴 / 결과 없음).
- 회귀 확인: `세종대로 110`(자동) 12건, `중구 태평로1가 31`(주소 대체 경로) 12건, `부산 해운대해수욕장`(버튼) 12건, `없는건물이름12345` → "찾은 곳이 없어요" 안내.

### T17. 묶음 카드가 다른 시설을 가림
- 증상(사용자 발견): 대구역 앞에서 `롯데백화점 대구점`이 목록에 없다고 느낌. 실제로는 같은 주소·좌표(북구 태평로 161)라 `대구역 · 2곳` 한 장에 묶여 있었고, 묶음 이름이 **대구역**만 보여 줬다.
- 원인: 묶음 이름을 "이름들의 공통 앞부분"으로 만들고, 공통이 3글자 미만이면 **가장 짧은 이름**을 썼다. 층만 다른 같은 시설(`○○지하상가 1층/2층`)에는 맞지만, **다른 시설이 같은 건물에 있는 경우**에는 한쪽을 지운다.
- 해결: 공통 앞부분이 3글자 이상이면 예전처럼(`○○지하상가 · 3곳`), 아니면 **이름을 나란히**(`롯데백화점 대구점 · 대구역`, 3곳 이상이면 `외 N곳`). 주소 줄에 `· 같은 자리 N곳`, 시설 수는 **합계**, 구분 알약은 **종류마다**(공중·개방), 펼침 안내는 줄을 따로 둬 잘리지 않게.
- 교훈: 묶기는 화면을 줄이지만 **정보를 지운다** — 묶음 제목은 안에 무엇이 들었는지 말해야 한다.

### T18. 어두운 모드에서 입력 글씨가 검게
- 증상(사용자 발견): 어두운 모드에서 "다른 곳" 검색창에 글씨를 치면 검은 글씨라 배경에 묻혔다.
- 원인: `<input>`은 부모의 `color`를 물려받지 않고 브라우저 기본값(검정)을 쓴다. 배경만 투명하게 두고 글자색을 안 정해서 생겼다.
- 해결: `.search input{color:var(--ink)}` + `::placeholder{color:var(--sub)}`.
- 교훈: 색 토큰으로 바꿔도 **폼 요소(input·select·textarea·button)는 따로 지정**해야 한다. 어두운 모드를 넣을 때 가장 먼저 볼 곳.

### T19. 검색한 장소가 사라지고 엉뚱한 곳이 "찾으신 곳"에
- 증상(사용자 발견): `대구 롯데백화점`을 검색해 **상인점**을 골랐더니 ① 기준 위치가 `달서구 월배로 232`(주소)로 바뀌어 무엇을 골랐는지 알 수 없고 ② "찾으신 곳"에 `상인공영주차장 화장실`이 떴다.
- 원인 ①: 핀 화면에서 좌표→주소를 다시 조회하며 `S.base.addr`을 주소로 덮어썼다. 고른 이름을 어디에도 남기지 않았다.
- 원인 ②: 이름 비교가 **양방향 포함**이었다. 군더더기 말을 뺀 `상인공영주차장 화장실` → **`상인`(2자)**이 `롯데백화점상인점`에 들어가 매칭됐다. 모듈 문서에 적어 둔 **"포함 + 종류어 검사"**를 앱에서 지키지 않은 것.
- 해결: ① 검색으로 온 이름을 `S.query`로 들고 **핀을 30m 넘게 옮기기 전까지 이름을 표시**(기준 위치 줄은 이름이 크게, 주소는 작게). ② **화장실 이름이 검색어를 품으면 확실**(`서울역` → `서울역(4호선)`), 반대 방향은 **4자 이상**일 때만.
- 덤: 매칭이 없으면 조용히 넘어가지 않고 **"○○에는 등록된 화장실이 없어요 + 민간 건물은 신고된 곳만 + 가장 가까운 곳 92m"**를 보여 준다. 실제로 롯데백화점 상인점에는 등록된 화장실이 없다(원본 확인).
- 회귀 확인: `롯데백화점 대구점` → 찾으신 곳 1곳 · `서울역` → 4곳 · `롯데백화점 상인점` → 안내 + 92m.

### T20. 자리가 남는데 줄이 바뀜
- `word-break:keep-all`과 함께 쓴 `overflow-wrap:anywhere`가 **단어를 미리 내려보냈다**. `break-word`로 바꾸면 넘칠 때만 끊는다.
- 교훈: `anywhere`는 "넘치면 아무 데서나 끊어라"가 아니라 **줄 계산 자체를 바꾼다**. 한국어 화면에서는 `keep-all + break-word`.

### T21. 검색 목록과 결과 화면이 서로 다른 말
- 증상(사용자 발견): `롯데백화점 상인점` 검색 줄에는 **🚻 상인역 외 1곳**(있다고 읽힘), 고르고 나면 **"등록된 화장실이 없어요"**.
- 원인: 검색 줄은 **120m 안의 아무 화장실**을 붙였고, 결과 화면은 **이름이 맞는 화장실**만 "찾으신 곳"으로 인정했다. 두 화면이 서로 다른 기준을 썼다.
- 해결: 검색 줄도 **이름 기준으로 가른다** — 이름이 맞으면 `🚻 이름`(초록), 아니면 `이 시설에는 없음 · 가까운 곳 92m (상인역)`(주황), 200m 안에도 없으면 `등록된 화장실 없음`(회색).
- 덤(같은 원인의 반대 오답): `서울특별시청`이 바로 그 건물의 `서울시청 본관 B1층 시민청 외부`를 **못 알아봤다** → 이름 정규화에 `특별시·광역시·특별자치시 → 시`를 넣었다.
- 교훈: **같은 사실을 두 화면이 말할 때는 기준이 하나여야 한다.** 화면마다 따로 규칙을 쓰면 사용자에게는 앱이 거짓말하는 것으로 보인다.

### T22. 이름이 포함된다고 같은 시설은 아니다
- 증상(사용자 발견): `동대구역` → "찾으신 곳"에 **동대구역치안센터**. 역 화장실이 아니다.
- 원인: 앱의 이름 비교가 **포함만** 봤다. 모듈 문서(위치 매칭 6장)에는 **"포함 + 종류어 검사"**로 적어 두고 데이터 쪽(`verify_locations.py`)에만 적용했고, 앱에는 빠뜨렸다.
- 해결: `kindDiffers()` — 긴 이름에서 짧은 이름을 뺀 나머지에 **다른 종류의 말**(치안센터·파출소·아파트·주차장·공원·학교·병원…)이 있으면 다른 시설로 본다.
  - 동대구역치안센터 ↔ 동대구역 → **다름** · 계산역아파트 ↔ 계산역 → **다름**
  - 서울시청 본관 B1층 시민청 외부 ↔ 서울시청 → 같음 · 서울역(4호선) ↔ 서울역 → 같음
- 교훈: **모듈에 적어 둔 규칙을 새 화면에서 다시 구현할 때가 위험하다.** 같은 판단을 두 곳에서 하면 한쪽이 빠진다 — 옮길 때 원문을 다시 읽는다.
