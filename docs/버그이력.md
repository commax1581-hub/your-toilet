## 상세

### T1. curl 한글 검색어 깨짐
- 증상: Windows Git Bash의 curl로 도로명주소 API를 부르자 결과가 0건이거나 엉뚱(숫자만 일치). 처음에는 "API가 줄임말을 못 읽는다"고 잘못 보고했다.
- 원인: 명령줄 한글 인코딩. Python `requests`로는 줄임말·띄어쓰기 없음·옛 이름 모두 정상 처리.
- 회귀 확인: 시험 호출은 스크립트와 같은 경로(Python)로.

### T2. 첫 번째 결과 채택
- 증상: `금산군 복수면 곡남리`(후보 264건), `대전광역시 서구`(24,966건)도 '정상'이 될 뻔함. 착한가격 `addr_util.py`는 번지까지 있는 가게 주소라 문제가 안 드러났다.
- 해결: 후보가 모두 같은 건물이거나 주소 끝(도로명+번호, 동·리+번지)이 정확히 같을 때만 채택, 아니면 '모호'. 자치단체코드로 얻은 시도·시군구 밖 결과는 '지역불일치'. 400곳 시험 모호 16 → 4.

### T3. 카카오가 못 읽는 주소 형식
- 해결: 번지·호 → `N-M`, 동·리에 붙은 번지 띄우기, 도로명에 붙은 건물번호 띄우기(`473번길`은 그대로), 층 범위 제거. 좌표 실패 791 → 569.
- 남은 실패는 도로명주소·카카오 모두 없는 주소(원천 오류).

### T4. 산지 핀 옮기기
- 근거: 300m 넘게 떨어진 126곳 중 이름이 거의 같아도 봉우리·골짜기 자체(`국사봉`, `고산골`), 엉뚱한 곳(면사무소·식당·여관 27곳).
- 원칙: 교차 확인용 장소검색도 검증 없이 좌표를 덮어쓰지 않는다.

### T5. 캠퍼스 건물 좌표 오답
- 증상: `태백중학교(행정동 2층)` → `태백중교`(693m), `한강시민공원(자연학습장)` → 공원 주차장, 공항 탑승구 → 주차장.
- 해결: 묶음 안에서 이 화장실을 가르는 말(공통 앞부분·층·방향 제외)이 장소명에 있어야 채택. 주차장·충전소 등은 그 말이 이름에 있을 때만. `야외`·`실내`·`고객` 등은 가르는 말로 안 씀. 2,070 → 1,023곳(표본 20곳 중 약 19곳 맞음).

### T6. history_v2 100행 제한
- 증상: `numOfRows=1000`을 줘도 100행만 와서, 첫 쪽만 본 비교가 틀림.
- 해결: 쪽 끝까지(`totalCount`까지) 받기. `info_v2`는 1,000행 가능.

### T7. 요일 말 부분 일치
- 해결: 요일 말을 긴 것부터 대조하는 정규식, `토`·`일` 한 글자는 `(토)`·`일)`처럼 괄호와 함께만. 시험: `test_hours.py`.

### T8. 옛 지번으로 조용히 찾아짐
- 증상: 가짜 다음 판 시험에서 도로명만 바꾸자, 도로명이 지역 밖으로 거부되고 바뀌지 않은 지번으로 옛 위치를 찾음.
- 해결: `update.py`에서 '도로명 지역불일치·주소없음 → 지번으로 찾음'은 `확인필요`로 표시하고 확인 목록(`new_bad_coords.csv`)에 넣는다.
- 회귀 확인: 같은 지자체 안 이전(도로명·지번 모두 바뀜)은 좌표가 바뀌고, 도로명만 엉뚱하면 확인 목록에 오른다.

### T9. 같은 건물을 캠퍼스로 판정
- 원인: 이름들의 공통 앞부분이 `별내도서관지`가 되어 `지하`·`지상`이 반으로 잘리고 `하`·`상`이 남아 "이름이 서로 다름"으로 판정. 먼저 넣은 `지상` 규칙이 효과가 없던 이유도 이것.
- 해결: `campus_coords.kind` — 이름마다 층·방향 말을 뺀 뒤 같은 이름이 70% 이상이면 같은 건물. 같은 건물 173 → 232묶음(887 → 1,198곳), 넓은 곳 W 5,083 → 4,822.
- 회귀 확인: 별내도서관(같은 건물), 스타필드하남(같은 건물), 부산시민공원·부경대학교(캠퍼스·단지).

### T10. 칸 경계 반올림
- 원인: 칸은 원래 좌표로 정하고 파일에는 소수 5자리로 반올림한 좌표를 저장 → 경계 바로 옆 19곳이 옆 칸 좌표가 됨.
- 해결: 반올림한 값으로 칸도 정함. `check_data.py`의 "좌표가 자기 칸 안" 검사가 잡았다(검사 규칙이 첫 실행에서 실제 버그를 찾은 사례).

### T11. 쉼표가 든 행정동
- 원인: `clean`이 쉼표 뒤를 "나머지 주소"로 보고 잘랐다. 행정동 이름(`중계2,3동`, `상계6,7동`)에는 쉼표가 들어간다. 잘린 `중계2`를 카카오가 `중계동 2번지`로 찾아 필지(B) 등급을 받았다.

### T19. 검색한 장소가 사라지고 엉뚱한 곳이 "찾으신 곳"에
- 증상(사용자 발견): `대구 롯데백화점`을 검색해 **상인점**을 골랐더니 ① 기준 위치가 `달서구 월배로 232`(주소)로 바뀌어 무엇을 골랐는지 알 수 없고 ② "찾으신 곳"에 `상인공영주차장 화장실`이 떴다.

- 회귀 확인: `롯데백화점 대구점` → 찾으신 곳 1곳 · `서울역` → 4곳 · `롯데백화점 상인점` → 안내 + 92m.

### T22. 이름이 포함된다고 같은 시설은 아니다

### T24. 역 좌표표에 같은 역이 두 번 (파일 목록 중복을 의심하지 않았다)
- 증상: 칸 구조를 비교하다 발견 — `rail_stations.csv` **1,233행 중 782행이 중복**(같은 기관·노선·역이 두 줄). 좌표 차이 중앙값 0m(같은 자리를 두 번 찍고 있었다). 화장실 행 합계 2,522도 부풀려진 수였다.
- 원인 둘: ① 받은 **파일 24개 자체에 중복**이 있었다(부산2·3·4호선 ⊂ 부산교통공사, 분당선 = 수인분당선) — 파일 이름이 다르니 다른 데이터라고 **믿었다.** ② 역명 **부기**를 떼지 않아 `강변`과 `강변(동서울터미널)`이 다른 역이 됐다(서울 56역).
- 해결: 칸 9개가 모두 같은 행 제거(2,210 → **1,923행**) + 역명은 부기 뗀 이름으로 묶기 → **841행 · 역 746개**(중복 0). 부기는 `역명원본`에 보존. 두 출처가 같은 역을 가질 때는 한 줄에 `국가철도공단 + 서울교통공사`로 적고 화장실 행 수를 출처별로 나눠 둔다.
- 재검증: 환승역 46곳 700m 초과 **0** · 우리 데이터 동명 역 963곳과 **중앙값 38m · 300m 이내 90%**. 1km 초과 38곳은 전부 **코레일 동명이역**(부산 중동 ↔ 부천 중동처럼 다른 도시) — 좌표 오류가 아니다.
- 교훈: **"파일이 여럿이면 내용도 다르다"가 아니다.** 포털은 쪼갠 것과 묶은 것을 같이 올린다. 합치기 전에 **행 중복률과 파일별 고유 기여도**를 먼저 센다. 그리고 **검증을 통과했다고 안심하지 않는다** — 1,233행짜리도 환승역 검증을 0으로 통과했다(중복은 거리가 0m라 오히려 잘 통과한다). **개수 자체가 맞는지**를 따로 봐야 한다.

### T25. 저장한 곳에서 열면 아무 일도 안 일어난다
- 증상: 앱을 **새로 켜자마자** 저장한 곳/최근 본 곳에서 항목을 누르면 상세가 안 열린다(콘솔에 `Cannot read properties of null (reading 'date')`).
- 원인: 상세 화면이 기준일(`S.index.date`·`RAIL.date`)을 읽는데, **목록을 한 번도 안 거치면 둘 다 없다.** 하단 탭이 생기면서 **목록을 건너뛰고 바로 들어올 수 있게 된 것**이 방아쇠였다.
- 해결: `openSaved()`가 `loadIndex()`·`loadRail()`을 먼저 기다린다.
- 교훈: **새 입구를 열면 그 입구로 들어온 사람이 무엇을 못 갖췄는지 본다.** 기능을 더한 곳이 아니라 **길이 새로 난 곳**에서 깨진다.

### T26. 지도에서 엉뚱한 핀이 켜진다
- 증상: 아래 카드를 넘기면 다른 자리의 핀이 켜진다. 머리글은 14곳인데 카드는 12장이었다.
- 원인: 역 핀을 `overlays` **앞쪽**에 따로 넣었는데 `selectCard(i)`는 `overlays[i] = 카드[i]`를 전제했다 — 역 개수만큼 밀렸다.
- 해결: 핀과 카드가 **같은 배열 하나**(`mapItems`)를 보게 했다. 덤으로 **역이 아래 카드 줄에도** 선다.
- 교훈: 같은 순서를 **두 배열이 따로 들고 있으면** 언젠가 어긋난다. 순서는 한 곳에서만 만든다.

### T27. '역'으로 걸렀더니 역이 사라졌다
- 증상: 종류 필터에서 **역**을 고르면 역 안 화장실이 0곳이 되고 지자체 카드만 남는다.
- 원인: `passRail()`에 "종류 필터가 켜지면 역 카드는 뺀다"고 적었다. 다른 종류(공원·관공서…)를 고를 때를 생각하며 쓴 줄인데, **'역'까지 함께 걸러 버렸다.**
- 해결: `S.f.ft === '역'`이면 오히려 **통과**시킨다.
- 교훈: "해당 없음"과 "정확히 그것"을 한 조건에 묶지 않는다.

### T28. 갱신해도 옛 지도 칸이 남는다
- 증상(코드 점검에서 발견): 주 1회 갱신을 해도 **한 번 본 칸은 영원히 옛 데이터**. 서비스워커가 `tiles-v1`에 담아 두고 **다시 받지 않기** 때문(cache-first, 서랍 이름 고정).
- 해결: 칸 주소에 기준일을 붙이고(`data/t/716_2571.json?v=2026-09-22`) 서랍 이름도 `tiles-2026-09-22`로. 새 기준일이 오면 **옛 서랍을 통째로 버린다.**
- 교훈: **오프라인 저장은 갱신의 반대편에 있다.** 저장을 만들면 "언제 버릴지"를 같이 정해야 한다 — 안 정하면 갱신이 사용자에게 도달하지 않는다.

### T29. 큰 글씨에서 제목이 한 글자씩 쪼개진다
- 증상: 320px × 가장 큰 글씨에서 머리글 "가까운 화장실"이 **세로로 한 글자씩** 떨어졌다. 단추 둘이 자리를 다 차지해 제목 칸이 한 글자 너비가 됐다.
- 해결: 제목·부제는 **말줄임**으로 끊고, 360px 아래에서는 머리 단추의 **글자를 접어 아이콘만** 남긴다. 역 상자 머리띠 문구도 짧게(`역 안 화장실 · 운영기관 제공` → `역 안 화장실`).
- 교훈: **가장 큰 글씨 × 가장 좁은 화면**은 별도의 화면으로 보고 한 바퀴 돌아야 한다. 글씨만 키우면 칸이 줄어드는 곳이 반드시 생긴다.

### T30. 오프라인에서 앱이 뜨지 않는다
- 증상(점검에서 발견): 서버를 끄고 열었더니 **빈 화면**. 콘솔에 파일 8개가 `net::ERR_FAILED`.
- 원인: 서비스워커가 저장한 이름은 `app.js`인데, 화면이 부르는 주소는 **`app.js?v=a68a7dfd`**(내용 해시, T23). 이름이 달라 저장본을 못 찾고 인터넷으로 갔다가 실패했다.
  - **두 규칙이 서로를 깼다.** "새 파일을 확실히 받게 하려고" 붙인 해시가, "인터넷 없이도 열리게 하려고" 만든 저장본을 무용지물로 만들었다.
  - 온라인에서는 티가 안 난다 — 인터넷으로 받아 오니까. **서버를 꺼 봐야 보인다.**
- 해결: 설치할 때 `index.html`을 읽어 **해시가 붙은 주소를 뽑아 함께 저장**한다. 목록을 두 곳에 적지 않아도 되고, 배포할 때마다 저절로 맞는다.
- 확인: 캐시 21개 → **29개**(해시 붙은 8개 추가) · 서버를 끈 채로 앱이 열리고 목록 15장·역 2곳·상세까지 정상.
- 교훈: **캐시 규칙은 서로 부딪힌다.** 파일 주소를 바꾸는 규칙과 파일을 저장하는 규칙이 있으면, 둘이 **같은 주소를 말하는지** 확인한다. 그리고 오프라인은 **실제로 끊어 보고** 검사한다.

### T31. 주간 갱신이 보고서 단계에서 죽는다 (리허설에서 발견)
- 증상: `python update.py`가 수집(53,588건)·비교·재처리(1,313곳)를 **다 마친 뒤** 보고서를 쓰다 `NameError: name 'moved_far' is not defined`로 멈췄다. 무거운 일을 다 하고 마지막에 죽어 결과물이 없었다.
- 원인: 보고서 문구에 *"좌표가 100m 넘게 움직인 곳"*을 적어 두고 **그 값을 계산하는 코드를 쓰지 않았다.** 갱신을 한 번도 돌려 본 적이 없어 드러나지 않았다.
- 해결: 이번 좌표를 지난 기준본과 대조해 `MOVE_LIMIT`(100m)을 넘는 곳을 모으고 `moved_coords.csv`로 남긴다.
- **고치자마자 값을 했다** — 첫 실행에서 4곳이 잡혔고 그중 하나가 **13,186m** 이동이었다(김해 주유소). 확인해 보니 우리 처리 오류가 아니라 **원천에서 같은 관리번호가 다른 시설로 바뀐 것**(이름·주소가 통째로 다름).
  → **같은 번호, 다른 시설** 감지를 새로 넣었다: 이름과 주소가 **함께** 바뀌고 좌표도 100m 넘게 움직였으면 `swapped_ids.csv`로 사람이 보게 한다. 행정구역 개편으로 주소 표기만 바뀐 것(광주 → 전남광주통합특별시)과 가르려고 **좌표 이동을 함께** 본다.
  → 이게 중요한 이유: 우리 **영구번호가 관리번호에 붙어 있어**, 번호가 재사용되면 **공유 링크가 다른 화장실을 가리킨다.**
- 교훈: **"한 번도 돌려 보지 않은 절차는 돌아가지 않는다."** 체크리스트에 적어 둔 그대로였다. 그리고 **검사를 만들면 첫 실행에서 뭔가 잡힌다** — 안 잡히면 검사가 잘못된 것을 의심한다.

### T32. 구청 안내가 이름으로 찾다가 길을 잃는다
- 증상(장학금 세션이 발견): 인천 **영종구·서해구·검단구** 화장실에서 오류 신고 안내가 **구청을 못 찾는다.** 앱 주소에는 옛 이름과 새 이름이 섞여 있다(옛 중구 83 · 서구 63 · 새 이름 448장).
- 파 보니 **더 오래된 구멍**이 있었다 — **특례시 13곳**(수원·성남·창원·포항·고양·용인·부천·안산·안양·화성·청주·천안·전주)과 **서울 강남구**도 처음부터 안내가 없었다. 합쳐 **7,409장(14.7%)**.
- 원인 사슬:
  1. `코드시군구`를 **주소 이름의 80% 다수결**로 정한다 → 이름이 바뀐 구(영종 52%·서해 78%·검단 66%)와 `수원시 팔달구`처럼 **두 마디로 적히는 특례시**에서 **빈칸**이 된다(420행 + 특례시 전부).
  2. `build_gov_links.py`가 그 빈칸을 키로 쓰니 **구청을 아예 수집하지 않았다.**
  3. 앱은 **주소 글자에서 이름을 읽어** 찾으니, 개편된 구는 이름이 달라 못 찾는다. **옛 중구는 제물포구·영종구로 갈려 이름으로는 가를 수도 없다.**
- 해결
  - `build_sgg_codes.py` 신설 — **자치단체코드 → 법정동 시군구코드**(주소 캐시의 법정동코드 227곳 + 주소의 현재 이름 1곳, 228/228). 원본의 `개방자치단체코드`는 **관리 지자체**라 주소가 옛 이름이어도 **이미 새 구로 갈려 있다.**
  - 카드에 **`sgg`** 칸 추가(`build_app_data.py`), `gov_sites.json`을 **시군구코드 키**로 바꾸고 인천 새 구청 4곳·특례시 14곳을 더했다. 일반구 39곳은 **모시(시청)**로 잇는다.
  - 앱은 코드로 찾되, **시도까지 어긋나면 주소를 따른다**(목포·부산 화장실이 양산시 소관으로 적힌 행이 3곳 있었다 — 다른 시도 기관을 안내하면 가장 혼란스럽다).
- 확인: **50,544장 전부** 구청을 찾는다. 옛 중구 주소 → 영종구청 45·제물포구청 38, 옛 서구 → 서해구청 46·검단구청 17. 영종·서해·검단·옛 중구 표본을 브라우저로 열어 **네 구청 누리집이 실제로 열리는 것**을 확인했다.
- **덤으로 잡은 것**: 옛 목록의 시도 단위 항목 3개가 **엉뚱한 식당 인스타그램**이었다(네이버 지역검색이 시청 근처 가게를 집었다 — 서울시청 대보정·세종시청 진웨이성·인천시청 베테랑종합어시장). 이름 매칭에서는 한 번도 쓰이지 않아 드러나지 않았다. 코드 키로 바꾸며 걸러냈고 **세종은 36110으로 제대로** 넣었다.
- 회귀: `python build_sgg_codes.py` → 228/228 · `python check_data.py` → 시군구코드 없는 카드 0 · 구청 못 찾는 카드 0.
- 교훈: **이름은 키가 아니다**(규약 1-1)를 화면에서도 지켜야 한다. 데이터를 코드로 이어 놓고 **화면에서 다시 이름으로 찾으면** 같은 자리에서 또 깨진다. 그리고 **다수결로 정한 값은 경계에서 조용히 빈칸이 된다** — 빈칸은 실패로 세지 않으면 보이지 않는다.

### T33. 구청 누리집이 다이소·버거킹·하나은행이었다

- 증상(장학금 세션이 267곳 전수 접속해 발견): "이 정보가 틀렸나요?"의 시군구청 링크 **14곳**이 엉뚱한 곳으로 갔다 — 가게·은행·카페·식당 6곳, 인스타그램·블로그 6곳, 죽은 주소 2곳(동해 `http`가 404 · 평창 옛 주소 `happy700.or.kr`). 배포본에서 **3,138장**이 영향(여수 476 · 서귀포 385 · 보령 315 …).
- 까닭: 네이버 지역검색이 `○○구청`에 **근처 가게**를 준다. 받는 쪽은 제목에 시군구 이름 두 글자가 있으면 통과시켰다 → `다이소 강북구청사거리점`이 강북구청이 됐다.
- **앱에서는 오류가 나지 않는다.** 링크를 열어 주기만 하니 틀린 주소도 잘 작동했다(T32·6-39와 같은 유형 — 쓰는 곳에서 안 보인다고 표가 맞는 것은 아니다).
- 고침: ① 기준 표(공통지식 `시군구_누리집.json`)를 장학금 세션이 고치고 `고친_기록`에 남김 → ② `build_app_data.py`가 그 표에서 다시 복사 → 앱 사본 267곳이 표와 같아짐 → ③ `build_gov_links.py`에 **세 가지 거르기**와 `--verify`를 넣고, 수집 결과가 표를 **덮지 않게** 후보 파일 + 차이 보고로 바꿈.
- **거르기도 두 번 틀렸다**: 처음 267곳에 걸었더니 19곳이 걸렸는데 대부분 우리 잘못이었다(동시 접속 시간초과 · 인증서 · 빈 제목 · 일반구 이름 · `전주시 대표사이트`), ②는 `통영시청 제1청사`까지 버렸다 → 판정을 **통과·버림·보류**로 갈라 남의 서버 사정은 **보류**로 세고, 이름은 모시 어간으로, 부속 표현(`본청`·`제1청사`)을 떼고 본다.
- **생존 검사는 이것을 못 잡는다**: `check_links.py`에서 14곳 모두 **200 OK**였다(다이소도 살아 있다). 생존과 정체는 다른 검사다.
- 회귀: 기록의 옛 값 14곳을 거르기에 넣으면 **14곳 모두 걸린다**(① 13곳 · ③ 1곳 — 동해 http 404) · `python check_data.py` → 구청 못 찾는 카드 0 · `python build_gov_links.py --verify` → **버림 0**(보류는 지자체 서버 사정이라 0이 아닐 수 있다 — 브라우저로 본다).
