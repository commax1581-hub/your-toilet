## 2. 설정 순서와 함정

### 2-1. 올리기 전 — 키 검사
`.env`의 **실제 키 값**으로 올라갈 파일 3,738개를 대조했다(패턴 검사가 아니라 값 대조). 결과 0건.
- 앱에 박힌 카카오 키가 **JavaScript 키**(도메인 제한되는 공개 키)이고 **REST 키와 다름**을 확인했다. 이 검사를 건너뛰면 서버 키를 공개 저장소에 올릴 수 있다.
- 이 프로젝트에는 `.env`가 **없다** — 착한가격 폴더의 것을 함께 쓴다(`addr_util.ENV_FILES`). 덕분에 실수로 올릴 파일 자체가 없다.

### 2-2. GitHub — `gh` CLI를 쓰면 한 줄
```
winget install --id GitHub.cli --source winget
gh auth login            # GitHub.com → HTTPS → Yes → Login with a web browser
gh repo create your-toilet --public --source . --remote origin --push
```
- **함정 1**: winget 설치 뒤에도 `gh`가 **PATH에 등록되지 않았다**. 전체 경로로 부르면 된다 — `& "C:\Program Files\GitHub CLI\gh.exe" auth login`.
- **함정 2**: 로그인 마지막 질문에서 화살표를 내리면 **「Paste an authentication token」**이 선택된다. 그냥 Enter(맨 위 = 브라우저 로그인)가 쉽다.
- **함정 3**: 브라우저에서 승인해도 **터미널을 닫으면 저장되지 않는다.** 터미널이 살아 있어야 인증 결과를 받아 온다. 일회용 코드는 몇 분 뒤 만료되므로 코드가 나오면 **바로** 진행한다.

### 2-3. Cloudflare Pages
| 단계 | 값 / 경로 | 함정 |
|---|---|---|
| 진입 | 컴퓨트 → Workers 및 Pages → 생성 → **화면 맨 아래 "Pages를 배포하려고 하십니까? 시작"** | 기본 화면은 **Workers용**. 가운데 `Continue with GitHub`를 누르면 Pages가 아니다 |
| 방식 | **기존 Git 리포지토리 가져오기** | 「파일 끌어서 놓기」를 쓰면 자동 배포가 안 돼 **매번 3,738개를 손으로** 올려야 한다 |
| 권한 | Only select repositories → `your-toilet`만 | 전체 저장소 권한을 주지 않는다 |
| 빌드 | 프로젝트 이름 `your-toilet` · 프레임워크 **없음** · 빌드 명령 **비움** · **출력 디렉터리 `app`** | 출력 디렉터리를 비우면 **파이썬·문서가 웹에 그대로 올라가고 앱은 안 열린다** |
| 재배포 | `git push` | 1~2분. 새 키·파일이 반영됐는지 **`?v=` 해시로 확인**한다 |

### 2-4. 카카오 — **무료 쿼터는 계정당 한 앱뿐**
가장 크게 헤맨 곳이다. *"서비스마다 앱을 나눠 쿼터를 분리하자"*는 판단이 **틀렸다.**

> 카카오 콘솔이 활성화 직전에 알려 주었다:
> *이미 카카오맵 API를 첫 번째로 활성화해 일간 무료 쿼터를 제공받는 앱(착한가격지도)이 존재합니다. 이 앱은 무료 쿼터를 제공받을 수 없으며, 활성화 시 요금이 발생하므로 월렛을 연결해야 합니다*

공식 문서에도 같은 문장이 있다 — *"카카오맵 API는 개발자 계정 기준 **첫 번째로 활성화한 앱에만** 무료 쿼터를 제공합니다."*

**→ 앱은 하나로 쓰고, 그 앱의 JavaScript 키에 도메인을 나란히 등록한다.**
```
http://localhost:8000
http://127.0.0.1:8000
https://goodprice-map.pages.dev
https://your-toilet.pages.dev
```
- 등록 위치: 앱 → **앱 키 → JavaScript 키 → JavaScript SDK 도메인**(예전 안내의 "플랫폼 → Web → 사이트 도메인"에서 화면이 바뀌었다).
- 새로 만든 앱은 카카오맵이 **꺼진 채로** 생성된다. 켜지 않으면 SDK가 이렇게 답한다 —
  `{"errorType":"NotAuthorizedError","message":"App(이름) disabled OPEN_MAP_AND_LOCAL service."}`
  **도메인 문제로 착각하기 딱 좋다.** 브라우저는 "스크립트 로드 실패"만 말하므로, **curl로 SDK를 직접 받아 응답을 읽는 것**이 가장 빠른 진단이다:
  ```
  curl -H "Referer: https://your-toilet.pages.dev/" \
    "https://dapi.kakao.com/v2/maps/sdk.js?appkey=<JS키>&libraries=services&autoload=false"
  ```
- 우리는 **카카오톡 공유를 쓰지 않으므로** 착한가격 때 필요했던 「제품 링크 관리」 등록은 하지 않았다.

## 3. 무료 쿼터 (2026-09-25 공식 문서 확인)

| 우리가 쓰는 것 | 하루 무료 | 초과 시 |
|---|---|---|
| **지도 Web(JavaScript) SDK** — 앱의 지도 | **300,000건** | 0.1원/건 |
| 키워드로 장소 검색 — 앱의 검색, 역 좌표 만들기 | **100,000건** | 2원/건 |
| 좌표로 주소 변환 — 핀 위치의 주소 | **100,000건** | 0.5원/건 |
| 주소로 좌표 변환 — 데이터 만들 때 | **100,000건** | 0.5원/건 |

월간 전체 **3,000,000건** 한도가 따로 있다.

**어느 정도인가**: 지도 SDK는 *지도를 한 번 띄울 때 1건*이다. 한 사람이 하루 2~3건 쓴다고 보면 **하루 10만 명** 규모에서 한도에 닿는다. 착한가격 지도와 나눠 써도 여유가 크다.
**먼저 닿을 쪽은 장소 검색(10만 건)**이다 — 검색창에 글자를 칠 때마다 부르기 때문이다(350ms 디바운스).
사용량은 콘솔의 **「제품별 사용량」·「시간별 사용량」**에서 본다(두 서비스 합계로 보인다).
